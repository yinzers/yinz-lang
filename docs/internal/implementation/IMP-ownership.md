# Ownership — Design Decisions

User spec: [`docs/reference/REF-ownership.md`](../../reference/REF-ownership.md)

> **Read first**: Yinz is NOT object-oriented — see [`.claude/rules/non-oop.md`](../../../.claude/rules/non-oop.md). Ownership modifiers are SIGNATURE-level keywords (declared at function definitions); body-level `.share()/.lend()/.give()` syntax does NOT exist. The compiler infers ownership at call sites from the callee's signature and renders the result as IDE muted hints. Only `.copy()` and `.freeze()` are body-level dot-postfix operations (with parens per [`.claude/rules/dot-postfix.md`](../../../.claude/rules/dot-postfix.md)). Locked r4, r10, r11.

---

## Ownership Concepts

Rust ownership semantics, Yinz surface syntax. Three modes for passing a value into a function:

- **`share`** — read-only access. Caller keeps ownership. Multiple shares allowed simultaneously.
- **`lend`** — mutable access. Caller keeps ownership. Only one outstanding lend at a time (no other share or lend during the borrow).
- **`give`** — ownership transfer. Caller loses the value; receiver gains it.

Plus two body-level operations on values:
- **`.copy()`** — produce a new owned value: a genuinely independent one for every type where independence is meaningful, and a compile error for the types where it is not.
- **`.freeze()`** — lock a binding from further mutation for the rest of its scope.

**Why English keywords instead of `&T`/`&mut T`/`move`**: Rust's `&'a mut T` syntax is the single biggest usability barrier in Rust adoption. Yinz uses plain English signature keywords (`share`/`lend`/`give`) declared at the function definition; the compiler infers them at every call site so the developer rarely types ownership at all. `.copy()` and `.freeze()` use dot-postfix-with-parens per [`.claude/rules/dot-postfix.md`](../../../.claude/rules/dot-postfix.md).

## Signature-Level Declaration (Explicit)

Function signatures declare ownership intent as keyword prefixes on parameters:

```ynz
function greet(share name: string) -> nothing { ... }      // function will only read name
function rename(lend player: Player) -> nothing { ... }    // function will modify player
function consume(give data: Data) -> nothing { ... }       // function takes ownership of data
```

The signature is the contract. Anyone reading the function knows exactly what it does with its inputs.

**OPTIONAL everywhere a parameter is declared** — on free functions with bodies and on contract method signatures inside `shape` declarations (`shape Foo { method(share self, ...) -> X }` — the parser accepts a bare position, `parser.rs:3996–4012`). Yinz has no function-type annotation syntax to consider as a third position — `ynz-ast`'s `Type` enum has no function variant and `parse_type_with_depth` (`parser.rs:900`) has no `function` arm (parked item 23, `.claude/plans/parked.md`). A bare position means the compiler figures out read-only vs. mutating from use (the `effective_ownership` fixpoint; for a contract, from the implementing function). **`give` is the one word that is never figured out** — a position is a give position only when the word is written, on a function or a contract alike ("Transfer — Who Else Holds This Value" below). The author may still type `share`/`lend` explicitly for emphasis; the compiler verifies it matches the body.

## Call-Site Inference (Implicit — No `.share()`/`.lend()`/`.give()` Body Syntax)

Call sites in Yinz follow the uniform inference rule ([`.claude/rules/inference.md`](../../../.claude/rules/inference.md)): the compiler reads the callee's signature and inserts the right modifier automatically. **There is no body-level syntax for `.share()`/`.lend()`/`.give()`** — those modifiers exist only in signature position; call sites get them via compiler inference and IDE rendering.

```ynz
greet(name)           // compiler reads greet's signature → name is shared
rename(player)        // compiler reads rename's signature → player is lent (mutated)
consume(data)         // compiler reads consume's signature → data is given (consumed)
print(data)           // COMPILE ERROR: data was consumed above; use .copy() if you need to keep it
```

The IDE renders the inferred modifier as muted text:
- **Neutral gray** for `share` (benign read-only)
- **Red-tinted** for `lend`/`give` (cautionary — mutation or transfer)

Click-to-make-explicit on a muted hint converts the source to the explicit signature-level form for the function-decl side, NOT to a call-site syntax (which doesn't exist).

**Why inferred-with-hints instead of inferred-only OR required-explicit**:

- **Inferred-only** (compiler picks, no visibility): mutation becomes invisible to readers. `healPlayer(player)` looks identical whether the function mutates or not. Bad for jr devs.
- **Required-explicit** (every call types ownership): too much noise; developers stop reading; the marker degrades to syntactic burden. Inverse anti-pattern — graveyard Entry 2.
- **Inferred + muted hint** (Yinz's choice): compiler does the work; IDE shows what happened; hover teaches WHY.

Consistent with type inference, lifetime inference, wait-point inference, allocator inference — one rule across all surfaces.

## Body-Level Operations: `.copy()` and `.freeze()`

These two are the only body-level dot-postfix ownership operations. They use parens per the dot-postfix rule.

### `.copy()` — produce a new owned value

```ynz
const backup = original.copy()       // a value nobody else reaches
saveForever(backup)                   // backup consumed (give inferred), original unchanged
```

**The ruling (Patrick, 2026-09-06; superseded the r4 "strict cheap-only" rule this section used to state).** `.copy()` returns a genuinely independent value for every type where independence is meaningful, and is a COMPILE ERROR where it is not. Nothing silently aliases, ever. There are exactly two buckets, no third.

The r4 text this replaced — "`.copy()` is only legal when every field is transitively trivially copyable; write a standalone `copy()` function for anything deeper" — described a compiler that never shipped. What shipped instead was an alias: `maybe`, `fixed`, union and `dynamic` all fell into a `.copy()` arm that handed back the receiver's own pointer while the type checker admitted the call, which produced one use-after-free and one silent wrong answer (v0.3 concurrency hardening, cluster C2). Deep-and-refuse is what removes that; a shallow copy would have re-introduced the same defect one level down and called it a design. Golden Rule 2 decides the tie against Golden Rule 10: "sometimes independent, sometimes not, depending on how nested your value is" is not something a junior developer can predict without documentation. If deep copying ever proves too slow on a real workload, the answer is an explicit cheaper operation with its own name — never a silent reinterpretation of `.copy()`.

**The one table.** `ynz_typeck::owned_copy::owned_copy_plan` (`crates/ynz-typeck/src/owned_copy.rs:147-332`) is exhaustive over `Type` with no `_` arm, and both consumers read it: `.copy()`'s lowering and the `background`-argument path (`emit_owned_copy`, `crates/ynz-codegen/src/emit.rs:28103-28387`, also exhaustive, no `_` arm). Neither classifies a type itself, so the two can never again disagree about what an owned copy is (`.claude/rules/authoritative-derivation.md`).

| Type | What `.copy()` does |
|---|---|
| `int`, `float`, `bool`, an `options` value | The receiver's bits ARE the copy — nothing can change what is behind them (`owned_copy.rs:150-156`) |
| `string`, `sensitive string` | A fresh string with an owner of its own (`StringClone`, `owned_copy.rs:154`, `:212-216`; `ynz_string_clone`): two names for the same bytes would agree, but two owners would free them twice. A `sensitive string` copy keeps the label |
| `number` (≤ 34 digits), `range` | Immutable contents in storage the producing frame owns: the receiver, inside a body. A `background` argument of one is re-homed onto the heap first (`number`) or refused (`range` — no re-homing path exists) (`owned_copy.rs:161-168`) |
| `shape` | Its own bytes into fresh storage (`ShapeMemcpy`, `owned_copy.rs:171`), then every field that owns heap gets a copy of its own (`deepen_shape_fields`, `emit.rs:5924-6002`): a string, an `array` or a `map` through `emit_owned_copy`, a nested shape or a `maybe` as a fresh heap cell holding a deep copy, an envelope union through `union_deepen_fn`, a `fixed<T, N>` field cell by cell, a channel as one more counted reference |
| `fixed<T>` | Its N inline cells into a fresh slot, and for a `string` or `shape` item a copy of each (a string copy, or a fresh heap cell holding a deep shape copy). `fixed` of any other pointer-item type is refused: a `fixed` has no per-item pointer to follow (`owned_copy.rs:173-186`) |
| `array<T>` | A fresh header and buffer, and — when the cells hold pointers — every item copied through the same table, all the way down (`owned_copy.rs:188-191`) |
| `map<K, V>` | A fresh header and its four buffers (`MapClone`, `owned_copy.rs:193`), then every value that is not a plain string gets a copy of its own (`emit_map_values_deep_copy`, `emit.rs:28555-28727`: `deepen_shape_fields` for a shape, `union_deepen_fn` for an envelope union, `emit_owned_copy` for a pointer value); a string key or value is copied by `ynz_map_clone_strings` (`emit.rs:28315-28352`) |
| `maybe<T>` | A fresh envelope cell, for the inner types the shared maybe-ownership core can follow: a simple value, a `number`/`range`, or a `shape`. `maybe<array<T>>`, `maybe<map<K, V>>`, `maybe<fixed<T>>` and `maybe<maybe<T>>` are refused (`owned_copy.rs:195-204`) |
| `sensitive<T>` | Copies and KEEPS the label, so the copy is still redacted wherever it is printed. Refusing would push people to call `.reveal()` just to get a copyable value, which is strictly worse for the secret. Only inner kinds whose copy IS the receiver's bits qualify, and `sensitive` wraps only `string` today |
| `number` wider than 34 digits (a bignum) | A fresh copy of its decimal text, as a `string` (`StringClone`): a bignum is owned text, released like a string (`owned_copy.rs:264-266`) |
| `channel<T>`, a task handle, a union, `dynamic C`, a loop's `MapEntry`, an unchecked `errors` value, `nothing`, a type placeholder, a generic shape | **Compile error**, with WHAT / WHAT-INSTEAD / WHY naming what to do instead |

A refusal is a real answer and it is loud: a user who can see the refusal is better off than a user handed an alias they cannot see. The refusal text lives with the plan (`CopyRefusal`, three slots) and renders through the `CopyNotIndependent` diagnostic template; the `background` face of the same ruling renders through `SpawnArgNotIndependent`. Under a `Give` label the refusal is skipped except for a named `fixed` whose items cannot be copied (its cells are kept with the spawner's frame): that case fires too, with the `SpawnArgNotIndependentHandedOver` text (decided: plan-caused hole, `git log --grep=HandedOver`).

### `.freeze()` — lock a binding from further mutation

```ynz
let config: ConfigBuilder = { rules: [] }
config.addRule("a", 1)
config.addRule("b", 2)
config.freeze()                       // lock from this point forward
runApp(config)                         // config still usable for reads (share inferred); no further mutation
```

The freeze flag persists for the rest of the binding's scope. Useful for build-then-lock patterns where mutability is needed during construction but should be prevented afterward.

## `const` Deep Immutability — Safety + Performance Contract

`const` is the load-bearing immutability primitive in Yinz. It is exactly equivalent to Rust's non-`mut` binding (Rust calls it `let`; Yinz calls it `const`).

### What `const` blocks

A `const` binding rejects ALL paths to mutation:

1. **Reassignment** — `constVar = newValue` is a compile error (already enforced as of M2 in `crates/ynz-typeck/src/check.rs` `check_assign`)
2. **Field mutation** — `constVar.field = x` is a compile error (enforced when field assignment lands in M4)
3. **Passing to a `lend` parameter** — the compiler refuses to infer the mutable modifier at the call site if the binding is `const`; compile error pointing to "declare with `let` if you need mutation" (enforced in M4)
4. **Passing to a `give` parameter** — same: compiler refuses to infer the transfer; compile error (enforced in M4)
5. **`.freeze()` is redundant** — `const` bindings are already locked; calling `.freeze()` is a no-op but allowed for stylistic uniformity

### Why this is load-bearing — Safety + Performance

**Safety — aliasing rules**: if `const` can be mutated through any path, then two `const` references to the same value could observe different state, breaking the language's promise that "two reads of the same `const` always return the same value." That promise is what makes `const` shareable across threads without locks — also what makes the borrow checker tractable.

**Performance — the LLVM contract**: a function parameter declared `share` (or inferred from a `const` binding at the call site) emits the LLVM **`readonly`** attribute. Combined with **`noalias`** (which Yinz can guarantee from the ownership system), the optimizer gets the same aliasing information that lets Rust beat C++ in benchmarks:

- `readonly` → optimizer knows this pointer's pointee never changes during the call → enables loop-invariant code motion, common subexpression elimination, and skipping spurious reloads
- `noalias` → optimizer knows no other pointer aliases this one → enables vectorization and reordering that C/C++ can't do (because any pointer might alias any other)

C has `restrict` for `noalias` but it's a programmer's promise the compiler can't verify. Rust/Yinz make it enforced at compile time via the ownership system. That's the performance moat.

### M4 codegen contract

When M4 lands, codegen MUST emit:

- `readonly` on every LLVM function parameter declared as `share T`
- `readonly` on every parameter inferred from a `const` binding at the call site (even if the signature is bare and the modifier was inferred from body usage)
- `noalias` on every parameter the borrow checker has proven non-aliased (most of them for `share`/`lend`/`give` per ownership rules)

Failure to emit these attributes is a perf regression even if the program is correct. The M4 plan's `### Performance` invariant subsection explicitly asserts this, and [`.claude/graveyard.md`](../../../.claude/graveyard.md) Entry 1 catches M4 plans that omit it.

### Forward-compatibility for shapes (M4)

When `shape` declarations land in M4, field assignment (`player.field = x`) becomes parseable. The typeck must reject field assignment when the receiver is a `const` binding, with a teaching error pointing the user to declare `let` if they need mutation. This is item #2 above and is the single biggest gap the design-lockdown plan was created to prevent.

## No Direct Array Indexing — `.get(index)` Returns `maybe<T>`

`items[5]` is a compile error. All collection access by index uses `.get(index)` which returns `maybe<T>`. Collections include `.first()` and `.last()` returning `maybe<T>`.

**Why**: Out-of-bounds array access is one of the most common runtime crashes and security vulnerabilities (buffer overflows) in systems languages. If the compiler can enforce safe access universally, there's no reason not to. The cost is slightly more verbose access; the benefit is the elimination of an entire crash category.

**Performance**: In release mode, the compiler eliminates bounds checks it can statically prove are safe (e.g., a `fixed<3>` accessed at index 1 — provably in bounds). Debug mode always bounds-checks. Performance impact is negligible in practice.

**Consistency**: Maps already use `.get(key)` returning `maybe<V>`. The same pattern applies everywhere. No special case for arrays — one rule, all collections.

## Transfer — Who Else Holds This Value (v0.3-M8 Phase 2; signed off 2026-09-03 — the v0.3-M8 plan's `audit.md` (`.claude/planning/active/2026-07-04-v0-3-m8-concurrency-completion/audit.md`) SIGN-OFF record; Phase 4 implements)

**Status**: designed in v0.3-M8 Phase 2, signed off 2026-09-03 (`audit.md`'s SIGN-OFF record; `git log --grep=m8-p2` for the design rounds); **SHIPPED in v0.3-M8 Phase 4** (`crates/ynz-typeck/src/effective_ownership.rs` `provenance`/`consumed`/`returns_fresh`, `scope.rs` `Origin`/`ConsumedBy`/alias classes, `check.rs` `check_transfer` — the one emit site). This section is the ONE home for the question *"may this value leave this frame for a sink that will free it?"* — a channel `send`, a `give` parameter in any call form, a `background` argument the spawn gives away. [`IMP-concurrency.md`](IMP-concurrency.md)'s channel-close section cites it for the channel instance; it does not restate the rule.

### The producer this section retires

A list of argument shapes at call sites is unbounded — every expression form the list omits is a hole (eight probes were run against the tree; seven found a live hole, and the eighth — `dynamic Contract` — ICEs in codegen before reaching one, so it confirms zero runtime exposure rather than a hole: `.claude/corpses.md`, first entry, and `git log --grep=m8-p2`). The fix is not another shape on a list. It is one **provenance** function, defined once, with an exhaustive match the compiler enforces, whose four-valued answer every sink consumes; one **binding-event** rule, exhaustive over every statement form that can make a name denote a value; and the whole-program facts the existing `effective_ownership` fixpoint already computes, threaded to those sinks instead of re-derived.

**Where this diverges from the v0.3-M8 plan, surfaced in the required form.** The plan's Phase 2 block (FRAGO 008) says the phase answers the question "by THREADING `effective_ownership` and never enumerating `Expr::` variants"; this design does ONE exhaustive `Expr` match, inside the authoritative module, because "what does this expression denote, ownership-wise" is a syntactic question by nature — it is the input the fixpoint itself consumes (`arg_is_binding`, `root_binding_name` and `place_path` are already `Expr` matches inside that module). The corpse bans a partial list re-derived at each CALL SITE; a single match with no wildcard arm, in the one owning function, is closed by the compiler's exhaustiveness check rather than by a reviewer's memory. Recorded here and in the Phase 2 sign-off packet. **Ruled** (packet item (i), 2026-09-03 — `audit.md`'s SIGN-OFF record): a single exhaustive, wildcard-free match in the owning module is the remedy for the corpse's ban on open per-site lists, not an instance of it — the plan's Phase 2 block sentence is amended to this wording under FRAGO 010 (`audit.md`).

### Where the authority lives

`crates/ynz-typeck/src/effective_ownership.rs` is the module. It already owns (a) a Kleene fixpoint over every parameter of every local function, converging under mutual recursion, seeded from declared `lend`/`give` and raised by body use; (b) the per-expression helpers `arg_is_binding`, `root_binding_name`, `place_path`. `root_binding_name` already has a pre-existing twin at `check.rs:11864` beside `effective_ownership.rs:658` — Phase 4 collapses it to the one definition this section's threading depends on, or this section's "one authoritative answer" claim rests on an un-collapsed twin ([`authoritative-derivation.md`](../../../.claude/rules/authoritative-derivation.md)). Two corrections to how the module has been described: the fixpoint runs in the same query as the body check but **after** it today (`check(...)` at `queries.rs:~423`, `effective_ownership::analyze` at `:503`), and it depends only on the parse and the signature tables, both in hand at `queries.rs:279–308` — so hoisting it above the body check is a reorder, not a redesign. Phase 4 performs that reorder; every consumer below assumes the report exists before any body is checked.

This design **extends that module** with three facts and one function, and forbids a second derivation of any of them anywhere else ([`authoritative-derivation.md`](../../../.claude/rules/authoritative-derivation.md)):

1. **`provenance(expr, bindings) -> Provenance`** — the syntactic answer to "what does this expression denote, ownership-wise". Exhaustive over `Expr` with **no wildcard arm**, so a new expression form is a compile error in exactly one function until someone classifies it; consumers never see syntax, only the four values below.
2. **`consumed[fn][i]: bool`** — a per-position fact in the same fixpoint loop: position `i` of `fn` is *consumed* when it is declared `give`, OR its body passes it (as a whole binding) to a consumed position, OR sends it (as a whole binding) on a channel. Monotone false→true; converges for the same reason `Writes` does. **The send case is gated on the parameter's DECLARED type**: the fixpoint runs before body checking and has no type environment (`effective_ownership.rs:475–491` classifies a `.send` receiver by method NAME and the `is_user_fn` test, never by receiver type), so "sends it on a channel" means: a builtin `send` (not a user function of that name) whose argument is the whole parameter, AND `FunctionDecl.params[i].ty` resolves to an owned-heap element kind (`channel_elem_drop(ty).is_some_and(transfers_source)` — `array`/`map`). A `number`/`int`/`string` parameter sent on a channel is never `consumed`; the only builtin `send` that takes an `array`/`map` is the conduit send (channel or handle, one send core), so the element type is the parameter's own declared type and needs no receiver lookup. It is a lower bound (a body that first rebinds the parameter with `let` and then sends the rebinding is caught by the emit site's alias classes, below, not by this fact) — it exists so a relay chain is reported in ONE compile, never to accept a program.
3. **`returns_fresh[fn]: Freshness`** — per function: `Fresh` iff every `return` yields a value nobody else reaches (a fresh expression, a `give` parameter, or a local whose initializer was fresh, or a local that a `let`/assignment of a fresh local handed its value over to: a store hands the value over, so the new name is fresh and the old one is gone); `MayAlias` otherwise (a `share`/`lend`/bare parameter or any piece of one; a call to a `MayAlias` or imported callee; anything unclassifiable). Bottom `Fresh`, raised in the same loop. Imported functions are `MayAlias`. **One exception, by declared return type**: a function whose return type is a `string`, `array`, `map`, shape, `channel`, `maybe` of a channel or a union with a shape variant is `Fresh` whatever it returns, because its `return` copies what is not a fresh value or an owned local (`owned_copy::copied_at_return`, `crates/ynz-typeck/src/owned_copy.rs:496-531`, the one predicate typeck and codegen's return seam share; see "Non-owned reads"). The same declared type makes an IMPORTED callee's result `Fresh` (its body is not visible, its signature says what its `return` does). A channel's copy is a counted reference (`ynz_channel_share`), taken by the callee's `return` for a read that does not move, so the caller's binding owns one reference and gives it back once. A call of a generic function is an owned value too: its declared return type is a type parameter, so the call's own instantiated type decides (codegen copies a heap-typed result at the generic `return`). A `maybe` of a string, shape, number, channel or envelope union is copied at its `return` too (the payload is cloned, celled or deep-copied; `copied_at_return` is the one answer for the return seam and for typeck). Only a `maybe` of an array or map, a `maybe` of a union, a `maybe` of anything else and a union with no shape variant still return a piece.
4. **`classify_binding_in_stmts(name, stmts) -> EffectiveOwnership`** — the existing per-name body classifier (`classify_param_in_block`) exposed over an arbitrary statement suffix. It never cared that the name was a parameter; the Auto-Arc caller-side proof below needs the identical question asked about a local over the statements after a spawn.

```rust
pub enum Provenance {
    /// This evaluation is the value's only holder. Transferable; nothing to consume.
    Fresh,
    /// Exactly the value a binding names (`Ident` / `self`). Transferable iff the
    /// binding's origin (below) permits; consumes the binding's whole alias class.
    Whole(String),
    /// A value someone still reaches through the named roots — a field, an index,
    /// a loop cell, a call that returns a piece
    /// of its argument. Never transferable; the fix is `.copy()` on the reached piece.
    Reaches(Vec<String>),
    /// Cannot classify (function-value call, dynamic-dispatch result, imported
    /// non-fresh callee). Never transferable.
    ///
    /// `.copy()` no longer lands here: since the v0.3 concurrency-hardening owned-copy
    /// fix, a `.copy()` that would not be independent does not compile at all.
    Unknown,
}
```

### Binding events, origin and alias classes (the typeck half)

Origin and alias class are properties of a **binding event** — the moment a name is made to denote a value — never of the name. `ScopeEntry` (`crates/ynz-typeck/src/scope.rs`) gains an **origin** and an **alias-class id**; both are (re)computed at every binding event from the provenance of the value being bound. An **alias class** is the set of live entries that denote or reach one value, so that consuming any member consumes all of them (`let other = rows` and `rows = other` close by the same mechanism, not by a special case). Class membership is keyed by ENTRY, not by name: a shadowed outer entry keeps its membership while the inner frame is live and is the entry `lookup` finds again once the frame pops.

**The binding-event rule is exhaustive over the places a name can be bound, with no wildcard.** `Stmt` has ten variants (`ynz-ast/src/nodes.rs`, count pinned by test). Exactly three of them bind a name, and one non-statement form does:

| Binding event | What it is in the AST | Effect on the NAME's previous entry (if any) | Origin / class of the new entry |
|---|---|---|---|
| `let`/`const` — first declaration | `Stmt::Let` | none | per the initializer table below |
| `let`/`const` — **shadowing** a name already in scope (same frame: `Scope::insert` replaces; inner frame: hides — both are legal today, probe `let rows = [1,2,3]; let rows = [4]` prints `1`) | `Stmt::Let` | the previous entry keeps its own origin, class and consumed state (it still names its old value; a same-frame shadow makes that value unreachable by name, but the release plan still lists it under its own declaration at the block's end: `a_binding_shadowed_in_its_own_block_is_still_released`, `crates/ynz-typeck/tests/release_plan.rs`) | per the initializer table below — a NEW entry, never a mutation of the old one |
| **reassignment** `name = value` | `Stmt::Assign` | the entry **leaves its class** (the class keeps its other members and their consumed state — they still hold the old value); the entry's consumed state is REVIVED for the code the assignment dominates only (a consumed name that is reassigned names a new value: `eat(rows); rows = [4, 5]; rows.count()` is correct; `eat(rows); if (c) { rows = [4] }; rows.count()` is not, see "Revive is path-aware") | per the initializer table below, computed from the assigned value |
| `for` loop variable | `Stmt::For` | none (frame-scoped; `Assign` to it is already a compile error, `check.rs:2444`) | `Cell` (a cell of the iterated value; never transferable); joins the class of every binding the iterated value reaches |
| every name a `for` destructure binds (`destructure_pattern`, `map_destructure_pattern`) | **not** a `Stmt::For` binding — the parser desugars each destructured name to its own `Stmt::Let { value: __shape.field }`, prepended ahead of the loop body (`parser.rs:2252–2274`; map form `:2417`) | none | a `Let` event, so it takes the initializer table below from `Reaches(__shape)` provenance — never transferable, joins the iterated root's class; unlike the loop variable, `Assign` to a destructured name is admitted (`check.rs:2436–2465`) and is covered by the `Assign` row above, not this one (parked item 25) |
| function parameter | `FunctionDecl.params` (not a `Stmt`) | none (`Assign` to a parameter is already a compile error, `check.rs:2436`) | `Param(declared modifier)`; its own class |

The other seven statement forms bind no name: `Expr`, `If`, `While`, `Return` (they only read); `Match` (arms carry a `MatchPattern`, not a binding — `is` narrowing refines a type, it does not rebind); `FieldAssign` and `IndexAssign` write THROUGH a name into a container — they never change what the name denotes, and as stores they hand the value over (see "Stores are sinks" below). `Expr` has no binding form at all (no closure or arrow-function variant exists in `ynz-ast`). If a variant that binds a name is ever added to `Stmt`, it fails the pinned variant-count test and the `match` in the one function that implements this table — the compiler, not a reviewer, asks for its row.

The initializer table, applied at every `Let` and `Assign` event:

| Value bound has provenance | Origin | Alias class |
|---|---|---|
| `Fresh` | `Owned` | its own (a new class) |
| `Whole(b)`, heap-typed | `Owned` (or `Unknown` when the store is refused) | its own — **`b` is handed over** (`check_transfer`, sink 4), so `a` is consumed and the new name owns the value |
| `Whole(b)`, value-like (`int`, `float`, `bool`, `number`, `range`, options, `string`, `sensitive string`; `effective_ownership::value_like`, `crates/ynz-typeck/src/effective_ownership.rs:303-324`, is the one table) | `Owned` | its own — the checker consumes nothing: a number, `int`, `float`, `bool`, `range` or option is copied bits, and a string (or bignum) is taken by the store seam when typeck says the read may move, else cloned (`own_string_for_store`, `crates/ynz-codegen/src/emit.rs:22446-22464`) |
| `Reaches(roots)` | `Reaches` (never transferable) | joins every root's class — if a root is given away, this name is consumed with it |
| `Unknown` | `Unknown` (never transferable) | its own in the live scope; the persisted record (below) joins it to every binding the expression mentions, since an untraceable result may hold any of them |

The reassignment rule in one line: `rows = other` is a store, so `other` is handed to `rows`, `rows` leaves its old class and owns a new one, and reading `other` afterwards is `ConsumedByStore`. The consumed-read mechanism itself is a straight-line walk; a give carried into the next pass of a loop is a separate check (see "A give inside a loop" below).

`consumed: bool` becomes `consumed: Option<ConsumedBy>` with `enum ConsumedBy { Given { callee, .. }, Sent { channel, .. }, Stored { place, .. } }` (`crates/ynz-typeck/src/scope.rs:13-45`; the cause fills the diagnostic; the consumed-read site selects the template by it) — one field, no parallel `Option<String>`. `Scope::consume(name, cause)` consumes the whole class (`scope.rs:412-444`). The `Stmt::Assign` arm of typeck (`check.rs:2436–2465`, today a pure type check on a non-`const`, non-parameter, non-loop `let` local) becomes the second caller of the ONE binding-event function `Stmt::Let` calls — never a re-implementation beside it.

### The transfer decision — ONE emit site

`check_transfer(expr, sink)` (`crates/ynz-typeck/src/check.rs:7682-7787`) is the only function that decides a transfer and the only place the three diagnostics below are emitted. Every sink calls it; no sink inspects syntax:

- `Fresh` → admitted, nothing to consume.
- `Whole(name)` → read the entry: `const` → the existing cannot-give-const refusal (extracted into a helper with a sink-supplied WHAT-INSTEAD — a sender wants `{channel}.send({name}.copy())`, not "declare it with `let`"); already consumed → `report_consumed_read` renders it (`Consumed`, `ConsumedBySend` or `ConsumedByStore`, by cause), once per read span: the read check (`resolve_ident`, which checks the consumed state BEFORE an `is` arm narrows the name, and the read of `self`) reports every read it sees, and this sink reports the read it could not see, an operand inferred live and consumed by another operand of the same statement (`eatBoth(rows, [rows])`); `Param(m)` with `m != give`, or a class containing such a parameter → **`ParamNeedsGive`**; `Reaches` / `Cell` / `Unknown` origin → **`TransferNeedsCopy`**; `Owned` or `Param(give)` → consume the class with the sink's cause.
- `Reaches(_)` / `Unknown` → **`TransferNeedsCopy`**.

**The sinks this milestone wires to it** (each is a give position; the list is of SINKS, which is closed and small, not of argument shapes, which is not):

1. `channel<T>.send(v)` when `channel_elem_drop(T)` is `Some(kind)` and `kind.transfers_source()` — the owned-heap element kinds `array`/`map` ([`IMP-concurrency.md`](IMP-concurrency.md) "Which element types"). `int`/`float`/`bool`/`string`/`number` channels are copy-through and never reach the helper.
2. Every declared-`give` parameter position of every call form — plain call, monomorphized generic call, UFCS dot-call (**receiver AND non-receiver arguments**), and `dynamic Contract` dispatch — through ONE argument-list normalization (`[receiver, args…]` — the same normalization `background_spawn_call_form` and `collect_aliasing_in_expr` already perform; Phase 4 makes the three call paths share it rather than adding a fourth loop). A position is a give position when it is declared `give` OR `consumed[callee][i]` is true — the second case is what reports a relay chain in one compile (below).
3. A `background` argument the spawn gives away — **and this sink is the liveness INFERENCE, not a `check_transfer` call.** The inference in `check.rs::check_stmts` (recorded through `record_spawn_arg_ownership`) chooses `Give` or `Copy` for a `Whole(name)` binding the user never annotated; nothing it chooses can be reported as an error against a `give` the user did not write. **A `channel<T>`-typed argument never reaches this rule at all**: the earlier `BgOwnership::Channel` branch (inside `check.rs::record_spawn_arg_ownership`) claims it first and shares it (`emit.rs::prepare_bg_arg_for_ctx`, `ynz_channel_share`) — a `channel<T>()` constructor argument is `Fresh` → `Owned` under provenance, but that origin is never consulted here because the channel branch runs before this rule sees the argument (parked item 20). For every other type, the rule, restated class-aware: infer `Give` iff the binding's origin is `Owned` or `Param(give)` AND no member of its alias class is read in any remaining statement or in a LATER argument of the same call; otherwise infer `Copy`. So `background consume(rows, rows)` copies `rows` at the first position and gives it at the last: the consuming read nulls the binding's slot, and a second read after it would clone a null (decided: C1l). A `Cell`, `Reaches`, `Unknown` or `Param(share|lend|bare)` origin therefore declines to `Copy` — **and "declines to `Copy`" means a `Copy` entry is still RECORDED for the argument, never nothing** (parked item 19): `for (row in matrix) { background producer(wire, row) }` is a correct program today (probe: prints `3`, `matrix` intact afterwards) and stays one because codegen's `is_heap_arg` gate (`emit.rs::prepare_bg_arg_for_ctx`) reads the PRESENCE of an entry in `background_arg_inferred_ownership`, not which variant it holds (`fr23_uaf_planned_red.rs:27` confirms the same reading) — an implementer who records nothing for a `Whole(name)` spawn argument hands the task a spawner-stack pointer instead of a heap copy (the fr23 use-after-free class). `bg_inferred` is not read only by the inlay-hint pass (`inlay_hint_passes.rs::collect_background_ownership_hints_block` is A reader, not the only one); codegen already copies by TYPE for a recorded `Copy`, so the decline changes no runtime behavior for that case — it only stops typeck from consuming a name the frame does not own, and makes the muted hint say "copied", which is what happens. The `Give` consume routes through the class, so a name that aliases the given binding is consumed with it — and because liveness is asked of the CLASS, `let other = rows; background f(rows); other.count()` infers `Copy` rather than consuming `other` under a program that runs correctly. The spawned call's own DECLARED `give` positions are sink 2 (`TransferNeedsCopy` on a loop cell there is correct: the callee's author wrote the word), because the `Expr::Background` arm runs `infer_expr` on the call.
4. A store of a heap value into a place — `list.add(v)`, `table.set(k, v)`, `x.field = v`, `x[i] = v`, a part of a container literal, `let b = a`, `b = a` — through `Checker::store_value` ("Stores are sinks" below). Its cause is `ConsumedBy::Stored`, its diagnostic `ConsumedByStore`.

**Stores are sinks; storing hands the value over.** Decided (Chief, 2026-11-13, "deny and teach"; commit `664924b`, `git log --grep="hands it over"`). Putting a heap value into a place — `list.add(v)`, `table.set(k, v)`, `x.field = v`, `x[i] = v`, a container literal built from named values, `let b = a`, `b = a` — is sink 4 of `check_transfer`: the place becomes the value's one owner, the source binding is consumed, and reading it afterwards is `ConsumedByStore` (WHAT / WHAT-INSTEAD / WHY below; it suggests `.copy()` or moving the line above). A value that is not an owner refuses the store, as at any sink: a parameter without `give` (`ParamNeedsGive`), a piece, a loop cell or an untraceable value (`TransferNeedsCopy`), a `const` binding (`check_transfer`, `check.rs:7682-7787`). Value-like types (`int`, `float`, `bool`, `number`, `range`, options, `string`, `sensitive string`) are never consumed by a store: a string is taken or cloned at the store seam, the rest are copied bits. `Checker::store_value` (`check.rs:6045-6066`) is the one entry; which built-in methods store is one table, `builtins::collection_store_positions`; a literal hands over every named heap part (`hand_literal_parts_over`, `check.rs:6108-6132`) and is then `Fresh`.

**Refusals that stand.** Each is a compile error today.
- **Store of a non-owner** (above): `ConsumedByStore` on a read after the store, `ParamNeedsGive` / `TransferNeedsCopy` on a store of a parameter without `give`, a piece, a loop cell or a `const`. Chief's 2026-11-13 "deny and teach" ruling.
- **Two stores kept by Chief, 2026-11-18 (card #493):** `let held: T | nothing = first`, where `first` is a `share` parameter (`a_share_parameter_stored_into_a_union_local_is_refused_with_the_teaching_text`, `crates/ynz-driver/tests/v03_m9_c1l_share_into_union_local.rs`); and `[mkm()]`, where `mkm()` returns a piece of a local array (`a_piece_stored_into_a_literal_is_refused_with_a_why_that_names_the_holder`, same file). The fix is `.copy()` at the store.
- **A `map` keyed by a `sensitive string`** is refused by design, not temporarily: a map would release the key as an ordinary string and compare keys with a comparison that is not constant-time (`MapKeyNotStorableSensitive`; PM ruling A, C7 review r1; `git log --grep="refuse map<sensitive string, V> again"`).
- **`GenericUnionBoundOutOfOrder`** (commit `b891644`): a generic call whose declared return union (`nothing | T`, `Tiny | T`) binds `T` to a union that would not be first in the instance's flat union is refused, because the value the instance returns keeps its own tags (`check_generic_fn_call`, `check.rs:8535-8806`, refusing through `refuse_bound_union_out_of_slot_order`, `check.rs:8822-8905`; `union_keeps_slot_tags`, `check.rs:12477-12489`; `a_generic_union_return_with_the_bound_union_not_first_is_refused`, `crates/ynz-driver/tests/v03_m9_c1n_generic_union_coercion.rs`).

**Temporary refusals** (Chief's 2026-11-19 ruling, via the Chief of Staff: "Land #93 with the map-key refusals marked temporary and build the support right after."). Both are `MapKeyNotStorable` from `check_map_key_type` (`check.rs:9639-9703`), whose text says "yet":
- a `map` keyed by a shape, an `array<int>` or any other type that is not one 8- or 16-byte value: support is built on card #518, started right after #93 lands;
- a `map` keyed by a `number` of more than 34 digits (`number<35>`, `number<50>`; template `MapKeyNotStorableWideNumber`): also temporary, but not on #518, because a working alternative exists (key by an `int` or `string` id, or by a `number<34>`).

**Refused, pending Chief's ruling** (each may change; none is decided):
- a `background` union passed to a parameter the generic callee declares as a bare type parameter (`BackgroundUnionToGenericParameter`, `check_background_union_argument_for_generic_callee`, `check.rs:9587-9625`);
- a `number<10>` into a `number<40>` variant of a union (`UnionVariantNotStorable`, template `UnionVariantNotStorableNumberPrecision`, `union_variant_refusal_diag`, `check.rs:12320-12346`; `crates/ynz-driver/tests/v03_m9_union_coerce.rs`, fixture `v0_3_m9_union_coerce_number_precision_refused.ynz`);
- a `fixed<string>` received from a task and kept across a later `wait`, and an unsized `fixed` parameter of a function built once (`IMP-concurrency.md` "Blocked types and workarounds");
- an unsized `fixed` field (`FixedFieldLengthMissing`, `check.rs:1589-1607`) and a function whose returned `fixed` length cannot be worked out, such as two functions that only return each other's list (`FixedReturnLengthUnknown`, `check.rs:1662-1687`). A callee that stores a parameter must declare it `give` (its own body is refused otherwise), so a call never stores one argument into another behind the caller's back: there is no call-site store analysis and no second walk of the module. The loop-carried check below covers a store of an outer binding in a loop like any other give.

**Revive is path-aware.** A reassignment revives a given binding only for the code it dominates. At the join after an `if`, a match or a loop, the binding is live only if EVERY path that reaches the join revived it: each arm that does not always return, plus the path that enters no arm (an `if` without else, a loop that may run zero times, a match with no `else` that is not an exhaustive options/union match). Otherwise it is maybe given, and reading it is the ordinary use-after-give error (the canonical `Consumed` text, its `{via}` slot naming the path that did not reassign it: `ConsumedBy::missed_revive`, set at the join, rendered by `missed_revive_clause`); a give made anywhere on an arm persists past the join as before. One mechanism: `Scope::revive` / `begin_branches` / `begin_arm` / `end_arm` / `end_branches` (`scope.rs:515-524`, `:573-633`) extend the consumed state, no second tracker. The loop-carried check below reads the same state at the end of the body. The transfer record stays flow-insensitive: a binding given on any path keeps its `Given` escape after a revive. The release plan therefore does not read the record for that: a reassigned owner is `ReleaseIfLive`, so a revived value is released and a given one is not (`Fate`, `crates/ynz-typeck/src/release_plan.rs:160-167`), and a release never comes early.

**A give inside a loop must not reach the next pass.** A give of a binding declared outside the loop that is still consumed when the loop body ends is rejected with the `Consumed` template (the loop named in `{via}`); a reassignment before the back-edge revives the binding, a block that always returns never reaches the back-edge. Only a binding the next pass reads (by name, in the loop condition or body) counts; a give the loop does not carry passes to the enclosing loop, which checks it the same way; a `while` condition is part of the loop, so a give made in it counts. The `background` liveness inference reads an outer binding in a loop as live, so it infers `Copy`, not a second `Give`.

### The persisted transfer record

`TypedModule::transfers` (`crates/ynz-typeck/src/transfer_record.rs`) is the ONE record of who holds what; the live scope's classes die with their scopes, this keeps the final partition for the scope-exit release pass (C5–C8). Per function: alias classes whose members are keyed by `DeclKey` and the unique codegen name (`BindingNames`, C4), each with

- **role** per member (`MemberRole`, `crates/ynz-typeck/src/transfer_record.rs:56-65`): `Owner` (only ever bound to fresh values or a `give` parameter), `BorrowedParam` (`share`/`lend`/bare parameter), `Piece` (ever bound to a piece, a loop cell or an untraceable value);
- **anchor** (`ReleaseAnchor`, `transfer_record.rs:137-150`; chosen by `AliasClass::anchor_for`, `:170-179`, and `anchor_of`, `:677-738`): `Founder` = the owner whose scope exits last, earliest declared on a tie; `CallerOwns` (a borrowed parameter is in the class); `NoOwner` (all pieces: the allocation belongs to code this function cannot see); `NoStaticFounder(OutlivedByNonOwner)` (a non-owner outlives every owner, so which value it holds at the owner's exit is known only at run time — reported, never guessed);
- **escapes** (`Escape`, `transfer_record.rs:111-124`) on at least one path: returned, given, sent, or stored (`Escape::Stored { place }`: the place owns the value from then on, a temporary included). A store never joins two classes; classes join only where a name keeps reading a piece of another value (a field, an item, a loop cell, a call result that is a piece of its argument) or an untraceable result.

**The two anchors with no static release point are C7's, decided** (Software Architect ruling, plan #17 C5a). The record reports them; it does not release them. Each is pinned by a typeck-fact test now:

| anchor | what C7 does | typeck-fact fixture (`ynz-typeck/tests/transfer_record.rs`) |
|---|---|---|
| `NoStaticFounder(OutlivedByNonOwner)` | nothing is released (a leak, never an early free). A read that would outlive its root is a copy (a copy owner), and a call result is an owned value (`copied_at_return`, a channel included), so no program that builds reaches it today: the `maybe<channel>` reproducer has two owners (`a_maybe_channel_an_imported_function_returns_is_an_owner_in_a_class_of_its_own`). The anchor stays as the honest answer for a non-owner that outlives every owner; no drop flag (decided: Chief Architect) | none reaches it; the analysis is covered by the class-anchor tests |
| `NoOwner` | the temporary is released at the end of the statement that made it (a piece of a temporary, a loop cell of a temporary); no binding has a release duty | `a_piece_of_a_temporary_is_recorded_as_no_owner`, `a_loop_cell_of_a_temporary_is_recorded_as_no_owner` (an imported function's result of a copied-at-return type is owned by its binding: `an_imported_functions_result_is_owned_by_the_binding_that_holds_it`) |

`NoOwner` is released at statement end; `NoStaticFounder` is never released (a leak, never an early or double free).

A hole in the recorder's own bookkeeping (an event with no function being walked or naming an undeclared binding, a binding with no codegen name, a class with no anchor candidate) is never skipped: it is kept as a string in `TransferRecord::internal_errors`, and `TypedModule::with_codegen_names` fails on it with the other record holes, so `codegen_query` reports the compiler-bug diagnostic and builds nothing.

Releasing a class must free every distinct object in it exactly once, container and stored elements alike (C6/C7). A leak happens only where the plan says so (`Omitted(UnsizedFixed)`, `NoStaticFounder`: `OmitReason`, `release_plan.rs:140-156`); an early or double free never.

### The persisted release plan

`TypedModule::release_plan` (`ReleasePlan`, `crates/ynz-typeck/src/release_plan.rs:1229-1240`) is the ONE record of what each scope exit releases; C6/C7 emit releases from it and derive no transfer fact of their own (`authoritative-derivation.md`). It holds one **total** list per exit edge, every binding of a heap-capable type that leaves scope there, last declared first:

| edge | key | lists |
|---|---|---|
| end of a block (function body, `if` body, loop body per iteration, match arm) | the `Block` span | that block's frame |
| `return` | the `Stmt::Return` span | every open frame, innermost first |
| errors auto-propagation | the span of the identifier read that fires it | every open frame, innermost first |
| a statement of a function that is, or may become, a state machine (C8 slice 6) | the statement span | every open frame, innermost first, as the scope is at the START of the statement: what a task dropped while parked there still owns |

Entries are keyed by `DeclKey` and the unique codegen name (`BindingNames`), never the user's name. A binding with no heap in its type (`int`, `boolean`, `options`, a `maybe` of those) is not listed.

**Fates and where each comes from** (one source per fact; `Fate`, `release_plan.rs:160-167`; `OmitReason`, `:140-156`; `ReleaseKind`, `:79-113`; `MoveSite`, `:200-209`):

| fate | meaning | source |
|---|---|---|
| `Release(kind)` | sole owner, not moved on any path to this edge | transfer-record anchor + live scope |
| `ReleaseIfLive(kind)` | moved on some paths, or on every path for a reassigned owner (an assignment may revive it): release if the slot is non-null; every move site nulls the founder's slot (`MoveSite`) | live scope (`ScopeEntry::consumed_on_every_path`), or `string_moves` for strings |
| `Omitted(Moved)` | given, sent or stored on every path | live scope |
| `Omitted(Returned)` | the returned value is or reaches its class | the returned value's holders |
| `Omitted(NotOwner / CallerOwns / NoStaticFounder)` | another member founds the class; a borrowed parameter is in it; a non-owner outlives every owner (an imported `maybe<channel>` result; nothing is released) | transfer-record anchor |
| `Omitted(UnsizedFixed)` | a `fixed<T>` of heap items whose length is unknown (the result of `filter`, `unique`, `limit` or `freeze`): no count, so the items leak. A signature's `fixed` has a length (`FixedLength`), so its items are released | the binding's held type |
| `Release(TypeParameter)`, `ReleaseIfLive(TypeParameter)` | the value's type is, or holds, a type parameter of a generic function: the body alone cannot say whether it owns heap, so the plan judges it as if the parameter owned heap (the same anchor, moves and returns as any owner) and codegen resolves `ReleaseEntry::held` per instance (`T` = `string` releases a string, `T` = `int` releases nothing and its slot is never nulled). A string stored from a `T` read is taken, not copied, when typeck recorded the store as a move (`heap_moves`), so the instance agrees with the plan | `heap_class_of`, anchor, live scope |

**Every binding whose value owns heap is listed, whatever the kind** (`heap_class_of`, `release_plan.rs:269-271`, one type fact): `string`, `array`, `map`, `channel`, background task handle, a flat shape with heap fields, a shape holding a shape (each shape-typed field is a heap cell; a recursive or undescribed shape is assumed to own heap), `maybe` / union / `fixed` with a heap-owning content, `dynamic`, a map entry with a heap-owning key or value, and every errors-capable value (the error object is heap). A bignum (`number` wider than 34 digits, decimal text) is listed as a `string`. A type that cannot own heap (`int`, `boolean`, `options`, a shape of ints, a `maybe` of bits) is not listed. How codegen releases each kind is C6/C7's job; the record only has to be complete, and the corpus parity test rejects an omission with no reason. Generic bodies are checked once, so their lists apply to every instance.

The crossing set reads only the kinds with a frame home across a suspension (`ReleaseKind::has_frame_backing`): a pointer in a frame slot (string, array, map, channel, handle) or bytes in a frame region (shape, nested shape, union, `maybe`, `fixed` list; "Frame regions for aggregates" below). An errors-capable local has one (its error and ok words in two frame slots, a union result's slot in a region: "Errors-capable values in a resume function" below), so it is read too; a kind widens that one predicate together with its frame home, never apart. A type-parameter value never reaches a resume function: a generic function is never a state machine. A local whose only crossing is its own release read is the `release_only` bucket of `CrossingNames` (the reads are added by `ReleaseReads::with_reads`, `release_plan.rs:565-571`): the guards that reject a read after a `wait` (Check 2, Check 2b, the M3d probe) skip it, so no pinned rejection changes.

**Strings.** A string is never statically moved: `string_moves` says a read MAY be taken by a store, and codegen decides at the store site. A `let`/`const` string with a record-listed last-use read that can precede the edge is `ReleaseIfLive`, otherwise `Release`; the listed reads are its move sites, so the plan and `string_moves` are one fact. A string given to a `give` parameter is handed over like any given value (the checker refuses a later read): the caller omits it as moved (`Moved`, or `ReleaseIfLive` when only some paths gave it) and the callee, which owns what it was given, releases it, so exactly one side does. A `share`, `lend` or bare string parameter stays the caller's. Only a string that founds its own class follows the give; a string joined to a piece's class owns a copy the class's give does not take, so its own scope releases it.

**Crossing set.** A release is a read at its edge. `crossing_local_names_with_provenance` scans the statements with those reads added (`ReleaseReads::with_reads`), so an owner crosses a suspension exactly when one separates its declaration from its release, by the one suspension detection; the typeck guards, the admission and M3d probes and codegen's frame layout pass the same reads (user names in typeck, codegen names in codegen). The user-name reads skip an owner whose user name the function declares for two or more bindings (sibling blocks reuse names): the crossing producer and its guards are keyed by the name and would judge it by another binding of that name, rejecting a program that compiled before the plan. The skip is deliberate and loses no guard verdict, because the skipped kinds (string, array, map, channel, handle) cross a `wait` legally; codegen's names are unique, so its reads and frame layout keep every owner (`resolve_function`, `release_plan.rs:990-1041`; `ambiguous_user_names`, `:1044-1053`). A move is a write to the founder's slot (`collect_crossing_writes`).

**Parity.** `ReleasePlan::parity_violations` (`release_plan.rs:1523-1618`) checks, per edge and founder, the fate against `Scope::consumed_classes` at the edge and the transfer record's escapes (`typeck/tests/release_plan.rs`, over every fixture and example).

### The one release helper

`Cg::release_fn` (`crates/ynz-codegen/src/emit.rs:29334-29345`; the per-form body, `release_form_fn`, `:29360-29455`) is the one place a heap value is freed: it emits one module function `ynz_release_<type>` per type, from `release_step` (`emit.rs:28990-29053`), an exhaustive match over `Type`. It frees exactly what a copy of the value allocates (`emit_owned_copy`, `emit.rs:28103-28387`, whose shape copy is the one seam `deepen_shape_fields`, `emit.rs:5924-6002`), so a value freed once per holder balances.

| value | what its release frees |
|---|---|
| `string`, bignum `number` (> 34 digits) | its bytes (`ynz_string_release`; a static string is left alone); a bignum is decimal text held as a string is |
| `array<T>` | each item by `T`'s release, then the header and buffer (`ynz_array_release`) |
| `map<K, V>` | each occupied entry's key (a string key is a raw pointer the map owns) and value, then the buffers (`ynz_map_release`) |
| shape | each field by its type: strings, arrays, maps, a nested shape (its heap cell: contents, then the cell), a `maybe` (its heap envelope cell), a union slot, a `fixed<T, N>` field (each cell's item), a channel (one counted reference) |
| `maybe<T>` | the payload a copy allocates (a string, a shape's heap cell, a `number`'s cell); in the cell flavor, the envelope cell. An array or map payload is not the envelope's (copy refuses it) |
| union | an envelope union is a slot: a shape variant's fields (inline) or its box cell (recursive union), a string, array or map variant; any other union is a `{tag, data}` view |
| `fixed<string>`, `fixed<Shape>` | each cell's item (a string, or a shape's heap cell and what it owns); any other heap item of a `fixed` is an internal error (the copy table refuses it). As a shape field the cells sit inside the shape and the shape's release walks them in place (`ReleaseHome::Field`, inline) |
| channel, task handle | one counted reference (`ynz_channel_free`); the handle aborts its task (`ynz_handle_free`) |
| errors-capable | the error object, or the ok payload |
| `dynamic` | internal error: no such value exists in generated code |
| type parameter | resolved per instance before `release_step` runs: an instance type that owns no heap releases nothing |

Replacing a stored value frees the one it replaces (`set`, index assignment, a field assignment, a `fixed` `set` or index assignment, a map `set` over a present key, whose handed-in key copy is freed too). `emit_errors_capable_release`'s ok payload and a plain union view release through the same `stored_release` (`emit.rs:29209-29260`): one dispatch decides what a stored value's release is. The `background` task ladder releases a task's own value with this helper (`BG_ARG_KIND_RELEASE_GLUE`, the descriptor's `size` is the glue's address); a channel's element drop glue is the same function. A callee with any `give` parameter keeps the flat free for the positions it may move a value out of: its `give` positions, and every position of an unknown callee. A position a plain or a suspending callee declares without `give` is borrowed, so the task's copy of it (a string, array or map) is released whole by the ladder (`a_borrowed_string_given_to_a_suspending_callee_is_released_once`). A `give` position keeps its own rule (deferred, see "Non-owned reads"). Calling the helper at scope exits is C7 (plain locals) and C8 (suspension frames).

### The transfer rule at an exit edge

One rule decides, at every exit edge on the plain path and in a resume function, whether a binding's value is released there: **the holder that owns the value at that edge releases it, and no other holder does.** The release plan's fates (above) are this rule written per binding. Its only inputs are the checker's consumed state and the transfer record's escapes, so codegen decides nothing of its own.

| What happened to the value before the edge | At this edge | Owner from then on |
|---|---|---|
| given (a `give` position of any call form), sent on a channel, or stored into a place, on every path | not released: `Omitted(Moved)`; the read that handed it over nulled the binding's slot | the callee, the receiver (the channel's element drop glue), or the place |
| given, sent or stored on some paths only, or the binding is reassigned | released if live: `ReleaseIfLive` is "release if the slot is non-null", so a path that moved it releases nothing and a path that kept it releases once | whoever holds it on the path taken |
| passed to a `give` parameter | the callee releases it at the callee's own scope exits; the caller omits it. A `background` task owns what is given to it (the spawn ladder frees nothing at a position the worker releases itself) | the callee, or the task |
| returned | not released: `Omitted(Returned)` | the caller; a `return` copies what does not move (`copied_at_return`) |
| kept, never moved | released: `Release` | this scope |

A read of a moved value is refused at compile time (`Consumed`, `ConsumedBySend`, `ConsumedByStore`), so a nulled slot is never read again. A callee never releases a value it only borrows (`share`, `lend` and bare parameters stay the caller's). That is why a value is freed exactly once, with no drop flag beyond the null check. A task dropped while Pending applies the same rule to the list of the statement it is parked at ("A task dropped while Pending (C8 slice 6)" below). Pinned by `v03_m9_release_safety` and `v03_m9_c7_*`.

### Scope-exit release on the plain path (C7)

A plain (non-suspending) function releases its heap locals at every exit edge of `TypedModule::release_plan`, through ONE emitter, `Cg::emit_release_edge` (`crates/ynz-codegen/src/emit.rs:30830-30836`, with `emit_release_edge_with`, `:30841-30871`), which calls `Cg::release_fn` (the C6 helper) for each entry whose fate releases. A state-machine resume function releases through the same emitter for the frame-backed kinds only, see "Scope-exit release in a resume function (C8 slice 2)" below.

**What is released** (`plain_releases_kind`, `emit.rs:30063-30082`, exhaustive): string, array, map, channel, task handle, flat shape, nested shape, `maybe`, envelope union, `fixed` list, errors-capable value and an admitted-SoA array (by field segment, `emit_soa_release`, `emit.rs:30958-31064`). Not released: `dynamic` and a map entry (never an owner of a slot). A union of heap variants with no shape variant (`string | array<int>`, `string | channel<int>`, and `string | int`) is a tagged union like any envelope union (`is_envelope_union`, `IMP-unions.md` "Heap-variant unions"), so it releases through the one helper by the variant its tag names (C7 slice 4). `string | int` carries the tag because without it the scope exit cannot tell the int's bits from a string pointer and freed the bits of `5` as a string (`a_union_of_a_string_and_a_scalar_does_not_free_the_scalar_as_a_string`); a union of value variants only (`int | float`) has no heap to release, so it gets no tag word and no release function (`a_union_of_value_types_has_no_tag_and_a_union_with_a_heap_variant_has`); a union with one variant beside `nothing` (`map<..> | nothing`) is still that variant's raw pointer and is classified as that variant. There is no `UntaggedUnion` kind.

- **Edges.** Block end (function body, `if` body, loop body per iteration, match arm), `return`, auto-propagation, each read by span from the plan; the value of a `return` is fully built before its edge runs.
- **Fates.** `Release`: load the binding's slot, call the helper. `ReleaseIfLive`: the same behind a null check; every plan `MoveSite` nulls the founder's slot when the value is taken (a `give`, a send, a store, a string taken by the store seam). A last-use string passed to a call that only borrows is not a take: the slot stays and the scope releases it.
- **No drop flags.** A read that would outlive its root is a copy, so no class has a holder that outlives its owner (decided: Chief Architect; a flag cannot make a view of a freed value sound). A call result is an owned value: a function copies at its `return` what does not move (`copied_at_return`), and for a channel that copy is a counted reference, `ynz_channel_share`, the count channels already have by design, as Rust's `Arc::clone` (no new counting mechanism, B4 "no garbage collector or reference counting for sequential code"). **The share is taken by the callee's `return`** (a parameter, an element or a field is shared; an owned local at its last use hands over the reference it holds), and the caller binds the result by move, so each reference has one owner and is given back once: by a binding's scope exit, a temporary's statement end, or the caller's own `return`. Decided: the Software Architect, within the Chief Architect's counted-reference rule (which first put the share at the holder of an untraceable result; that left an owned local a callee returned with an orphaned reference, and a `maybe<channel>` an imported function returned with no founder). A local `maybe` of a channel releases its payload (`ynz_channel_free`); a `maybe` in a shape field or a list does not, so its copy and release stay what C6 made them. An IMPORTED callee's result of a copied-at-return type is owned by the same reading of its declared return type. A task handle cannot be named in a signature, so no function returns one. A union that holds a channel (`string | channel<int>`) owns one counted reference like any channel holder: a wrap or a copy of its slot shares it (`ynz_channel_share`), its release gives it back once (C7 slice 4).
- **Unbound temporaries (`NoOwner`).** A fresh value no binding holds is released at the end of its statement.
- **Reassignment.** The old value is released at the assignment, behind the same null check. A reassigned binding copies at every place read (its `let` is a view only while nothing writes the binding, and the reassignment is that write; `non_owned_reads` never judges a reassignment a view), so it owns every value it holds and nothing it replaced leaks. An errors-capable local releases its old result through its original slot: the old words are snapshotted, the new result is copied into a region of the assignment's own (a call's result slot is per call site), and the original slot is rebound (`assign_errors_capable`, `emit.rs:30589-30644`).
- **Early exit from a loop.** A `return` or an auto-propagation inside a plain `for` body releases the copies of the loop variable (array, `fixed` and map-entry loops) that the iteration end would have released: `Cg::open_loop_copies` holds them while the body is lowered, `release_at_return` (`emit.rs:32456-32466`) and `release_at_propagation` (`emit.rs:32469-32483`) release them through `release_owned_read`, the helper the iteration end uses. A state-machine loop whose body suspends holds its copies in frame slots instead (C8 slice 3 section below).

**Move sites, temporaries, owners and returns.**

- **Move sites carry a cause and a kind.** `MoveSite { founder, founder_codegen_name, kind, cause }`. `cause` is `Handed` (a read typeck consumed: give, send, store, spawn give; the value always leaves the founder) or `LastUse` (a string last-use read: it leaves the founder only if the store seam takes it). Only a founder whose kind the plain emitter releases (string, array, map, channel, handle, flat shape) has sites.
- **Where the slot is nulled.** `Handed`: the identifier read itself (`lower_expr_node`, `emit.rs:23249-24389`, `Expr::Ident`), so every sink (call argument, send, spawn, store) is covered by one hook. `LastUse`: `own_string_for_store` (`emit.rs:22446-22464`) and `own_read_for_store` (`emit.rs:22632-22728`) when they take the string instead of copying it, through the slots remembered for the loaded value. A last-use string passed to a call that only borrows is not a take: its slot stays and the scope releases it. A resume function nulls the local slot and, for a parameter or a crossing local, the frame slot that backs it (`MoveSlot`, see the C8 slice 2 section).
- **`ReleaseIfLive` is "release if the slot is non-null"** for every kind.
- **Reassignment.** `Stmt::Assign` releases the old value when its binding is a released owner. Order: evaluate the value, load the old slot value (a `RHS` that took it already nulled it), store the new value through the store seam, then release the old one; a flat shape snapshots its old bytes first because its per-site region is reused. A reassigned owner is released at its exits like any owner, and `Moved::EveryPath` becomes `ReleaseIfLive` for it (a later revive may restore a value). The plan lists the assignments that release (`ReleasePlan::assign_release`).
- **`give` parameters.** The callee releases a `give` parameter at its scope exits like an owner; the caller's slot is nulled at the give. The spawn ladder does not free an argument at a `give` position (the callee owns it); other positions release deep.
- **Temporaries.** `TypedModule::temporaries` (`Temporaries`, `crates/ynz-typeck/src/temporaries.rs:89-111`; the test, `is_temporary`, `:443-485`) names each fresh heap value no binding holds (a Yinz call result, an array, map or shape literal, a fresh string, `.copy()`) and the release point it dies at: the statement, a `while` condition, or after an `if`, `match` or `for` as a whole. A value that enters a union slot, a `give` or store position (a map `table[key] = v` key included) and the piece of a `maybe` or union read are not temporaries. Codegen opens a frame per statement (`Cg::open_temporaries`, `emit.rs:31711-31713`; `open_temporary_frame`, `:31729-31841`): one entry-block slot per temporary, nulled at the statement's start; `lower_expr` stores the value into its slot where it is built (`bind_temporary`, `emit.rs:32192-32395`); the statement's end, a `return` and an auto-propagation release every non-null slot through `Cg::emit_slot_release` (`emit.rs:31655-31697`), the one emitter that `emit_release_edge` also calls. A state-machine function opens frames the same way for every statement it lowers with `lower_stmt` (a statement with no suspension, so an entry-block slot lives from its start to its end inside one resume), and releases at its `return` and auto-propagation too; a statement that suspends (`lower_sm_stmt_with_wait`) opens a frame whose slots live in the heap frame (`Cg::open_wait_temporaries`, `emit.rs:31724-31726`, see the C8 slice 2 section).
- **Take.** A string, array, map or nested-shape field read off a call result and kept by a `let` or assignment (`ReadVerdict::Take`) is taken without a copy: `lower_taken_field` (`emit.rs:27793-27827`) loads the field, nulls it in the temporary's region and marks it moved; the temporary's release skips the null field. A nested shape is a heap cell, so its bytes move into the binding's region and the emptied cell is freed (`shape_bytes_to_owned`, `emit.rs:4152-4170`, as `maybe_to_owned_taking` does for a returned payload), and the cell flavor of a shape release returns on a null cell ONLY for a shape some `Take` of the module moves out (`NonOwnedReads::takes_nested_shape`); every other cell release frees unconditionally, as Rust's `Box` drop does, and `lower_taken_field` refuses to null a cell whose release does not check (pinned by `v03_m9_c7_slice4`). Under its own name only: a union or alias annotation wraps the value, which stays a copy. The binding owns the taken value: the checker's binding event and the `Take` verdict read the one predicate `non_owned_reads::is_taken_piece_of_a_temporary` (`crates/ynz-typeck/src/non_owned_reads.rs:95-150`). Pinned by `v03_m9_c7_slice2` (`binding_a_piece_of_a_fresh_temporary_takes_it_without_a_copy`: 2 allocations, 2 frees) and `v03_m9_c7_slice3b` (`a_nested_shape_taken_from_a_temporary_is_not_copied_and_balances`: 0 extra cells or strings).
- **Copy owners.** A binding whose every event is fresh, a `give` parameter or a read typeck judged `MustCopy` owns its value and is released like any owner. The record keeps the value span of each event and applies the joins when it is built (`TransferRecorder::finish`, `transfer_record.rs:564-583`, takes `non_owned_reads`): a `MustCopy` event joins no class and makes no piece. A `Take` is bound as a fresh value by the checker only where no name reaches the temporary. The `Take` verdict agrees: a call result that may be a piece of its arguments (a generic callee returning one of them) is not a temporary to take from, so a field read off it copies and the binding owns the copy (`ReadTracker::takes_a_piece_of_a_temporary`, `non_owned_reads.rs:544-563`). The early release reads (suspension guards) are built before the verdicts and the final reads must cover them.
- **Every owner founds its own allocation.** `found.or(backup)` joins `backup` to the class of `found` (the result may reach either). `AliasClass::anchor_for(member)` (`transfer_record.rs:170-179`) makes every `Owner` of a class its own founder, with or without escapes; a `Piece` whose scope strictly encloses an owner's may still point into it, so that owner keeps the class anchor (nothing is freed early). A fate reads what happened to the binding's OWN value: the live scope's consumed state is per class, so it counts only where a read naming this binding gave, sent or stored it (`MemberFacts::moved_directly`), and a move site nulls only its own binding's slot. A dot-call reaches a user function only on a `Shape` or `dynamic` receiver (`provenance`, as `is_fresh_string_expr`), so a user function named `or` does not make the builtin `or` read as `Fresh`.
- **Returns.** A string, array, map, shape, channel, `maybe` of a channel or envelope union that a `return` does not move is copied at the `return` (`copied_at_return`, `owned_copy.rs:496-531`; a channel by a counted reference; a union by the return's own persist, deep unless the value moves), so it marks no binding returned; any other type keeps the class spread (`Checker::returned_holders_of`). The returns_fresh fixpoint reads a `let`/assignment of a fresh local as a hand-over (the new name is the fresh one), so a union built through an intermediate `let` and returned is `Fresh`: its caller binds it by move and nothing is copied twice or orphaned (`a_union_returned_from_a_local_or_a_parameter_is_owned_by_its_caller_once`). A call result of a union type is a temporary like any other (`temporaries.rs` releases it at the statement end).

**Slice 3 forms.** A local `maybe` is an envelope in an entry-block slot (its shape and number payloads sit in entry-block slots, its array and map payloads are the binding's own); a union binding is a VIEW of a slot it owns; both release through `local_release_fn` (`ReleaseForm::Local`). A binding takes the payload a returned `maybe` carries (`maybe_to_owned_taking`). `begin_assign_release` (`emit.rs:30181-30274`) snapshots the old inline storage of a flat shape, `maybe`, union or `fixed` list before the new value reuses its per-site region.

**Parked, with the reason.**
- *`is` on a non-shape variant* (`is string =>`) does not parse or resolve (`check_is_arm_pattern` names shape variants only), so a heap-variant union is held, passed, returned, stored and released but its payload cannot be read back yet (#418).
- *A generic temporary that an instance makes a union or a channel* cannot be written: the `.copy()` of such a `T` is refused in codegen, and a generic call inside a generic body is not instantiated. A string, array, map, shape or `maybe` `T` is released per instance (`Cg::open_temporaries`; "The spawn ladder (C8 slice 5)" below for the `maybe`); a generic `give` parameter or local of any `T` is released per instance (`Release(TypeParameter)`).
- *Heap-variant unions as container elements or map values* (`array<string | array<int>>`) cannot be written: a union type does not parse inside a type argument.

Pinned by `v03_m9_release_safety` (ASan, both optimization levels, counters) and `v03_m9_c7_*`.

### Scope-exit release in a resume function (C8 slice 2)

A state-machine resume function releases through the one emitter, `Cg::emit_release_edge`, at the same edges as a plain function: block end (`lower_sm_block`, `crates/ynz-codegen/src/emit.rs:11190-11218`; `release_at_block_end`, `:32412-32453`), `return` and auto-propagation. `Cg::releases_in_instance` (`emit.rs:30117-30136`) is the one predicate of what it releases: exactly the kinds with `ReleaseKind::has_frame_backing`, the kinds the crossing set reads. An errors-capable local is one of them (C8 slice 4b); a `fixed<T>` of heap items whose length is unknown is `Omitted(UnsizedFixed)` in the plan and its items leak.

- **A local lives in an alloca, the frame keeps it across a suspension.** A resume re-reads each parameter and crossing local from its frame slot into the local's alloca, so the frame slot is the truth at every resume. A move site nulls both: the local's slot and the frame slot that backs it (`MoveSlot`, `Cg::frame_slot_of`, `emit.rs:30668-30682`: the parameter's index or the crossing slot). Nulling only the alloca would be undone at the next resume and the scope exit would free a value that was handed away. A block-end release also nulls the released frame slot, so a later drop of the frame (the drop entry, C8 slice 6) cannot free it twice; `return` and propagation leave the function and do not.
- **A reassignment** releases the value it replaces for the same kinds (`begin_assign_release`); the new value reaches the frame slot through the statement's flush, a read that took the old value nulled it first, so the assignment releases nothing then.
- **Temporaries of a statement that suspends** (`lower_sm_stmt_with_wait`) live in frame slots after the crossing locals, not entry-block allocas (a resume gets a fresh stack frame). Typeck records them (`Expr::Wait` no longer suppresses its operand; `Expr::Background` still does), `wait_temporary_slot_count` (`emit.rs:14472-14537`) reserves one slot per temporary at every statement `stmt_needs_sm_walker_for` selects (the predicate the resume function routes by, taking its inputs instead of a `Cg`), at the three `n_locals` sites (layout, child-size memo, resume function), and `Cg::open_wait_temporaries` hands them out. Each slot's address is computed in the entry block (it dominates every state block), nulled at statement start and after its release, so a loop's next pass never frees the previous value. Overrunning the reservation is an internal error. A string, array or map temporary is a pointer in its slot; a shape, `fixed` list, `maybe` envelope or union temporary has a frame region behind its slot ("Frame regions for aggregates" below).
- **A handle local leaving scope stops its task.** Its release is `ynz_handle_free` (`ReleaseStep::Handle`, `emit_release_body`, `emit.rs:29484-29583`, the call at `:29572`), which aborts the child at its next suspension, through the same path (`handle_leaving_its_block_stops_the_child_optimized` and `..._unoptimized`, `crates/ynz-driver/tests/v03_m8_handle_scope_pin.rs`). Decided by the Software Architect on the Chief Architect's confirmation: "stop" is the semantics; there is no detach or join rule, so a task that must finish keeps its handle live until then (`h.receive()`; `bg_arg_handle_send_array.ynz`).
- **The spawn ladder and a worker's own release.** A suspending worker releases the frame-backed kinds of its `give` parameters at its scope exits, so the ladder frees nothing at such a position (`suspending_callee_param_ownership`, `free_kind_of_a_given_argument`); other positions keep their kind. A task dropped while Pending releases its frame through the drop entry ("A task dropped while Pending (C8 slice 6)" below); the rest of the ladder is "The spawn ladder (C8 slice 5)" below.
- **The error path of a narrowed re-read** (`.failed()` checked or propagated before) cannot run and has no plan edge: it releases temporaries and loop copies only (`release_at_narrowed_error_path`, `emit.rs:32490-32501`).


### Copies held across a `wait` (C8 slice 3)

A copy a suspending statement makes lives in a slot of the heap frame, not in an SSA value: a resume gets a new stack frame, so only the frame reaches the release.

- **One mechanism.** `Cg::hold_copy_in_frame` (`emit.rs:32100-32127`) puts the copy's pointer in the next reserved frame slot and adds it to the innermost open temporary frame (the same `TemporarySlot` list `open_wait_temporaries` fills). The statement end (`close_temporaries`), a `return` and an auto-propagation release it through `emit_slot_release`, null-checked, and the release nulls the frame slot. The slots come from the pool `wait_temporary_slot_count` reserves, and `copy_slot_count` adds one per `MustCopy` read in the statement itself (two for an iterated map: key and value). Only a string, array or map copy is held (the kinds a frame slot keeps); a staged union and a staged shape have their own regions ("Frame regions for aggregates" below). A statement routed to the walker for a CPU group alone has no heap-frame temporary frame (`lower_sm_stmt_with_wait` opens one only when `stmt_needs_sm_walker` holds, `emit.rs:11972-11979`; `wait_temporary_slot_count` reserves slots only for such statements, `emit.rs:14509-14527`), holds nothing (`hold_copy_in_frame` returns false when the innermost open frame is not a heap-frame one, `emit.rs:32106-32108`) because it has nothing to hold: it stages no suspending-call argument, and a loop copy made there is an internal error (`hold_loop_copy`, `emit.rs:23170-23192`). Nothing leaks: of the 81 `v0_3_m3d_*` fixtures (the CPU-group fixtures), the 78 that exit normally end with `alloc == free`; the other three (`cpu_child_panic`, `spike_e_panic`, `spike_f_cancel`) abort on purpose and write no counter.
- **Loop copies.** A suspending `for` over an array, `fixed` list or map opens an iteration frame (`open_iteration_frame`) per pass: the loop variable's copy (or the map entry's key and value copies) is held in it, and `close_temporaries` releases it at the iteration end, while a `return` or propagation in the body releases it through the open frames. A body that does not suspend keeps the SSA release (`release_sm_loop_copy`, `held` skips it).
- **A fresh iterable is evaluated once.** A fresh array or map that typeck recorded as the suspending `for` statement's heap-frame temporary is evaluated once before the header and read back from its slot (`hold_loop_iterable`, `loop_iterable_pointer`); a place is still re-read each pass, so a write that replaces it in the body is seen.
- **Staged argument copies.** A `MustCopy` argument of a suspending call is copied by `stage_suspending_call_arg_bits` (`emit.rs:18024-18159`) and held in a frame slot, released at the statement end after the callee completed. A `give` position holds nothing: the callee releases it (slice 2). A shape value the argument expression built is staged from a frame region, not from the heap or the stack ("Frame regions for aggregates" below).
- **CPU-group results.** The result of a spike or fused member is bound to the host's result slot as a frame-backed local, so the slice 2 release plan releases it like any local (`producer_p5_*`); nothing more was needed.


### Frame regions for aggregates (C8 slice 4a)

A shape, a nested shape, a `fixed` list, a `maybe` and an envelope union are inline bytes, not a pointer a frame slot keeps, and a resume gets a fresh stack, so their bytes live in a region of the heap frame. Rust keeps a value that crosses an await inline in the future's state; a region is that, and no allocation is added (Golden Rule 8).

- **A crossing local** has one moved-flag slot (`Cg::sm_region_flags`) in front of its region: a shape its bytes (`shape_frame_slots`), a `fixed` list its cells, a `maybe` the 16-byte envelope then its payload bytes (a shape's, a decimal's, or an envelope union's 16-byte view and slot, `maybe_region_payload_bytes`), an envelope union its slot (`union_frame_slots`). A bind copies into the region, a move or a release sets the flag, a bind clears it, and a resume re-derives the local from the flag (`null_if_moved`), so a value given away on one path is not released again. A reassignment snapshots the old inline bytes before the copy (`begin_assign_release`).
- **A temporary of a statement that suspends** takes a pointer slot, and a region behind it when its kind has one (`temporary_home`, `emit.rs:14344-14432`, the one answer behind `wait_temporary_slot_count` and `Cg::open_temporary_frame`): a shape, nested shape, `fixed` list, call-result `maybe` envelope (16 bytes; its string, cell or number payload is a heap pointer already) or union. `Cg::bind_temporary` moves the value in (one memcpy; a union persists with `deep` false, so the region takes what it owns) and returns the region as the expression's value, so every later reader reads it. A `maybe` of an envelope union is a region of the 16-byte envelope, then its 16-byte view and its union slot (`TemporaryRegionKind::MaybeUnion`; `bind_temporary` persists the call's union into the slot with `deep` false); an errors-capable temporary has a home of its own (below, "Errors-capable values in a resume function"). A field taken out of a temporary (`let name = make().name`) is nulled in it as on the plain path (`lower_taken_field`), because a resume function releases its temporaries too.
- **Staged arguments.** An argument of a suspending call stays at a stable address: a temporary is its region; a shape value the expression built that no temporary covers (a `give` position, or a shape owning no heap; `Temporaries::staged_shape_arguments`) is moved into a region reserved per argument (`staged_argument_slot_count`, `Cg::stage_shape_in_frame`), which the callee owns at a `give` position. An envelope-union argument is persisted into the callee's `Param` region and that region is held in a frame slot and released after the statement, unless the callee takes it; at a `give` position the region takes the boxes (the binding is moved).
- **Staged `maybe` arguments.** A `maybe` call result at a `give` position (not a temporary) is staged like a shape: `Temporaries::staged_arguments` records it, `Cg::stage_value_in_frame` (`emit.rs:31852-31900`; `stage_maybe_payload`, `:31912-31993`) moves its 16-byte envelope into a region reserved per argument (`staged_region_slots`), whose payload is a heap pointer or value already. A `maybe` of an envelope union is not staged. A `fixed` call result is not staged (`has_staging_region`, `crates/ynz-typeck/src/temporaries.rs:545-552`, answers true only for a shape, a `maybe` of a non-envelope-union and a decimal128 `number`). A signature's `fixed` has a length (`FixedLength`; `IMP-collections.md` "`fixed<T, N>` in function signatures"), so a returned `fixed` reports its `count`; only an unknown-length `fixed` (from `filter`, `unique`, `limit` or `freeze`) reads `count` 0.
- **Not yet.** A `give` argument that is a named `maybe` or `fixed` local still travels by pointer (the plain-local forms are unchanged).

### Errors-capable values in a resume function (C8 slice 4b)

An errors-capable local releases through the same emitter as any other (`ReleaseKind::ErrorsCapable.has_frame_backing`). Its frame home is the one a crossing errors local always had: the error word and the ok word in two frame slots (three for a decimal), refreshed into a companion `{err, ok}` struct on every resume, and for a union result the union's slot in a region.

- **The original slot.** `bind_sm_result_and_flush` records the binding's pointer slot (`ec_original_slots`). A read that narrows the local re-points `locals` at the success value, so the scope exit, a move and a reassignment all go through the original slot (`release_slot`), never `locals`.
- **A take nulls both frame words** (`MoveSlot::extra_frame_slots`, `Cg::frame_words_of`): a move site, a block-end release and a string the store seam takes (`string_take_ec_words` carries the ok word's frame slot), so the next resume reloads no word to release again.
- **A reassignment** snapshots the old result's two words through the original slot (`begin_assign_release_errors_capable`), lets the generic store rebind, and releases the snapshot after the store; the statement's flush carries the new words to the frame (a union result's region is overwritten only by that flush, after the release).
- **Auto-propagation** returns the error of the propagating local (`Omitted(Returned)` at its own edge) and releases every other open binding (`release_at_propagation`). The error path of a narrowed re-read has no plan edge and releases temporaries and loop copies only.
- **A crossing union result** is persisted into its region with `deep` false: the slot the caller copied out of the callee's `Return` region owns the boxes, and the region replaces it as their one home.
- **The ok word of a `maybe<envelope union>` result** is a stack maybe pair over a union view (`ec_standard_over_slot`), not a heap envelope cell, so `emit_errors_capable_release` releases it through the `maybe`'s Local form. A cell form would free a pointer that was never allocated (pinned by the plain-path fixtures `v0_3_m9_c8_s4b_maybe_union_errors_plain_{hit,miss}`).
- **A `maybe` a suspending callee returns** is taken by its binding (`maybe_to_owned_taking`) as a plain call's result is: the shape or number payload is a heap cell the return made. A crossing `maybe<shape>` takes it into its region too; a decimal payload is copied.
- **A `fixed` of unknown length.** The plan records `Omitted(UnsizedFixed)` for a list of unknown length whose items own heap, and its items leak. A signature's `fixed` always has a length (`docs/internal/implementation/IMP-collections.md`, "`fixed<T, N>` in function signatures"), so `KNOWN_PLAIN_LEAKS` is empty (`crates/ynz-driver/tests/v03_m9_c7_leak_sweep.rs:46`).
- **An unbound errors-capable temporary of a statement that suspends** (`wait consume(label(1).or(fallback))`) keeps its `{err, ok}` pair in a frame region behind its slot (`temporary_home`): 16 bytes for a string, array, map, shape, `maybe` of a string, scalar or shape, or a bignum ok word; the pair, the 16-byte view and the slot (`ErrorsUnion`) for an envelope union; the pair, the `maybe` pair, the view and the slot (`ErrorsMaybeUnion`) for a `maybe` of one (`bind_temporary`, `maybe_union_payload_into`). A decimal128 `number` result keeps no home (its ok word points into staging; nothing to release). Pinned by `an_unbound_errors_temporary_is_released_for_every_inner_type` (plain and suspending consumer). Not built: a crossing errors local passed to a `give` parameter cannot be written (an `errors` type is not a parameter type).

### The spawn ladder (C8 slice 5)

A `background` argument is the task's own value, and the ladder (`SpawnStateFnFuture::drop`, or the CPU closure's `emit_bg_arg_frees`) releases it once. The spawn site (`prepare_bg_arg_for_ctx`, `emit.rs:24471-24887`; `lower_sm_background_spawn`) decides who owns what; the free kind a slot carries (`BgArgFreeKind`, wire kinds `BG_ARG_KIND_*`) says how the ladder frees it.

- **The consumed original is released after the copy, on every path.** A binding the spawn consumes (`SoleHolder::ConsumedBinding`: its slots were nulled at the read) that the task receives a copy of is released right after the copy, in a plain spawner and in a resume function alike; the same for a fresh shape the spawn copies (`SoleHolder::FreshTemporary`: a call result or literal, which `ShapeMemcpy` cannot transfer because its storage is the spawner's frame, and whose statement-end temporary `Expr::Background` suppresses). A consumed `maybe` binding is released the same way, in its `Local` form (`release_maybe_original`: what its scope exit would have done); a fresh `maybe` call result is NOT released here, its statement-end temporary is (releasing it too is a double free). A `give` `maybe` position of a suspending callee keeps its envelope cell as `OwnedCell`, like a given shape: the callee nulls the frame slot, so the ladder frees the cell through the descriptor's own pointer. A `give` `maybe` whose payload has a cell of its own (a shape, a decimal) also has that cell freed by the ladder, because the callee's `Local` release frees the payload's contents but not a cell: a plain callee through the shell glue (`given_maybe_shell_release_fn`), a suspending one through a second `OwnedCell` entry (`OwnedMaybeCells`, the payload cell's pointer read from the envelope at the spawn). `ConsumedBinding` is recorded for the statement form and for the handle form (`let task = background f(x)`): an ident `Give` without the statement's `remaining` can only come from the callee's declared `give` parameter, which the call check consumes. Pinned by `a_handle_form_spawn_releases_the_consumed_original_once`, `a_suspending_spawner_releases_the_array_a_spawn_consumed`, `a_fresh_shape_a_spawn_copies_has_its_original_released`, `a_consumed_maybe_string_given_to_a_plain_task_is_released_once` and its siblings (`v03_m9_c8_s5`).
- **A union argument has one owner.** The task's slot (a heap cell for a plain callee, the callee frame's `Param` region for a suspending one) takes the boxes of a sole-holder argument (`mark_union_spawn_argument_moved`: the view is marked moved, no clone) and deep-copies one the spawner keeps. A suspending task's region has a `BG_ARG_KIND_RELEASE_GLUE` entry releasing the slot's contents (`sm_union_arg_free_kind`), except at a `give` position, where the callee releases its own parameter. Pinned by `a_union_parameter_of_a_spawned_task_owns_one_copy_and_frees_it` (five spawner forms, plain and suspending, `give` and borrowed).
- **A `MapEntry` argument owns its halves.** `value_to_stable_bits` copies the entry into a 16-byte cell and deep-copies a shape, `maybe` or decimal half; the spawn also copies a string key and a string, array or map value through `emit_owned_copy` (`copy_map_entry_halves`), because the cell otherwise holds the map's own pointers and the spawner's scope exit frees the map under the task (a use after free; ASan, `a_spawned_map_entry_owns_a_copy_of_its_key_and_value`). `bg_mapentry_release_fn` (`emit.rs:32571-32678`; one function per key and value type, the `ReleaseGlue` of every `MapEntry` position, `release_glue_free_kind` before its `give` rules) frees every copied half and the cell.
- **A given flat shape's cell is the ladder's, by pointer.** A suspending callee releases the fields of a flat shape it takes at a `give` position and nulls its frame slot (the slice 2 rule), so the ladder cannot find the cell there. The descriptor carries the cell's own pointer (`BG_ARG_KIND_OWNED_CELL`, `BgArgDropEntry::cell`, 32-byte entries) and frees it with `ynz_free(cell, size)`; every other kind writes 0 there and reads its slot. A plain callee keeps `HeapShape` (its closure frees the cell from the context). The drop entry of a Pending task (C8 slice 6) does not read a given shape parameter's frame slot for the cell: it is null after the callee's release, and the ladder owns the cell (`a_parked_task_given_a_flat_shape_releases_its_fields_and_the_ladder_frees_the_cell`). Pinned by `a_shape_given_to_a_spawned_suspending_task_has_its_cell_freed_by_the_ladder`.
- **A value a handle delivers.** `h.receive()` of a plain `maybe<T>` result copies the callee's `{flag, bits}` pair into a counted cell (`RET_KIND_VALUE_MAYBE`, `ynz_alloc(16)`), as a `maybe<T> errors` result's ok word already is one, so the receiving binding owns the envelope and its payload and releases it like any call result. A decimal128 `number` (34 digits or fewer) still sits in the handle's own buffer (`ec_borrowed_ok`: the binding drops the error object only). A `number<40> errors` result does not: its ok word is the text the task allocated and the handle hands over (`RET_KIND_EC_WORD`), so the binding owns it and frees it like any string. A union or `maybe` of a union is not the plain `maybe` cell either: it is the moved union cell ("A completion nobody receives" below). A completion nobody receives is released by the handle ("A task dropped while Pending (C8 slice 6)" below). Pinned by `a_maybe_received_from_a_handle_is_owned_by_its_binding`, `a_number_received_from_a_handle_is_not_freed_by_its_binding`, `a_received_bignum_errors_result_is_released_with_its_binding`.
- **Generic `T` temporaries.** A `T`-typed temporary that is an explicit `.copy()` (`Temporaries::is_type_parameter_copy`) is a minted `maybe` envelope cell in an instance whose `T` is a `maybe` (`MaybeCellClone`) and releases in the cell form. A union or channel `T` cannot reach it: its `.copy()` is refused in codegen. Pinned by `a_type_parameter_copy_instantiated_as_a_maybe_is_released`.

### A task dropped while Pending (C8 slice 6)

A task whose future is dropped before it returned (the runtime shut down, its handle was freed) releases what its frame holds through **the drop entry of its resume function**. Nothing runs on the normal path.

- **The resume function is the drop entry.** `SpawnStateFnFuture::drop` stores the complement of the frame's `resume_point` (`!rp`, always negative: a state number never is) and calls the resume function with no waker. The resume switch's default target is the *drop dispatch*, which switches on the complement to one block per suspension state (`register_drop_state`, `emit.rs:10790-10960`; state 0, never polled, releases the parameters). The block reloads the frame slots as the continuation state does (`reload_params_from_frame`), releases the open statements' temporaries (`release_open_temporaries`), releases the state's list with `emit_release_edge` (every release null-checked), drops the awaited callee frames the same way (the parent's block calls the child's own resume function with the complement of the child's `resume_point`), and returns Ready. A held task handle is released by the list like any local (`ynz_handle_free`).
- **"Returned" is a reserved `resume_point`.** Every Ready return stores `ynz_abi::FRAME_RESUME_POINT_RETURNED` (`i32::MAX`, `build_resume_ready_return`, `emit.rs:11072-11082`); the runtime's drop skips the entry for a frame holding it. Cost: one i32 store per task at its Ready return (the state a completed Rust future also has), no per-task flag, no per-wait or per-poll cost (a park already stores its state; the unwind guard runs only when the resume function unwinds). A resume function that unwinds leaves its frame mid-statement, so `poll` marks the frame returned on the unwind path only (`ReturnedOnUnwind`), and the drop skips the entry. The group-member "done" marker is the same value.
- **The list is typeck's, per statement.** `ReleasePlan::suspension_edge` (`release_plan.rs:1267-1269`; `EdgeKind::Suspension`) holds, for each statement of a function that suspends or that CPU promotion may make a state machine (`possibly_cpu_promoted`, the pre-rollback closure of `cpu_promotion_candidates`, one producer shared with `compute_cpu_promotions`), every open frame as the scope is at the START of the statement, judged like a `return`'s list. A founder a read inside the statement hands over is `ReleaseIfLive`, and the move site nulls its slot: the drop entry releases it only when the park came first. A call statement also counts the call statements after it (`RawEdge::reach_end`), because codegen overlaps such a run as one group that parks once. Codegen finds the statement from the parked source offset (`innermost_statement`, `emit.rs:10669-10684`) and decides nothing. The list is not "every non-null slot": a borrowed parameter and a view are non-null slots the task does not own, and an embedded callee frame keeps the slots of its previous call.
- **Sites.** Wait-sleep (its drop block frees its own frame's `Sleep` box through `ynz_rt_async_sleep_free`, null-checked, and nulls the handle slot, so the runtime's drop of the root frame and of the recursion chain finds null: each box is freed once, by its own frame; an embedded child's box has no other owner; invisible to the alloc counters, pinned under LeakSanitizer), inline callee poll, heap-boxed callee poll, conduit (`emit_conduit_suspend_point`), independent I/O group, fused group, CPU spike group and the loop back-edge yield each register their continuation state. A group parks once for all its members: an I/O member is dropped by its resume function, or, when it already returned (`resume_point == RETURNED`) with its result still in the return slot, that value is released (`DropMember::returned_value`, `callee_result_type`); a CPU member whose handle slot is null has finished with its result unclaimed in the result slot and is released the same way (`CpuDropMember`). A running CPU member keeps its handle, which the runtime detaches with the frame: a spawned CPU task cannot be cancelled and owns its argument context until it ends, so that context stays allocated while the process exits.
- **A completion nobody receives** belongs to the handle. `ynz_rt_spawn_handle` takes `result_release`, a `void(err, ok)` the spawn site emits per return type (`handle_result_release_fn`, `emit.rs:31406-31525`: a string, array or map word; a `maybe`'s counted cell; an errors-capable pair as the companion struct; null for a result that owns no heap and for a `number`, whose ok word is in the handle's buffer). `ynz_handle_free` closes the outbox and releases what was delivered before; a task that finishes after the close finds `try_send` refused and releases its own result. `handle_result_release_fn` covers a string, array or map word, a `maybe`'s counted cell, and an errors result of those, of a scalar, of a `maybe` of a non-union payload (the ok word is the counted cell) and of a bignum (its text); `None` for a result that owns no heap. An envelope union result (`-> Thing`, `-> Thing errors`, `-> maybe<Thing>`, `-> maybe<Thing> errors`: `handle_union_variants`) is MOVED out of the child's frame at the spawn wrapper: the return slot holds the address of the union region inside the frame, freed right after the completion is read, so `ynz_rt_spawn_handle` takes a move glue (`result_move`, `handle_union_move_fn`, `emit.rs:31202-31298`, ret kind `HANDLE_RET_KIND_UNION`) that `memcpy`s the slot into one cell of its own (the completion's ok word; none for a failed task); the slot of a `maybe` of a union is the union's, `none` as its tag, so the same move serves it. Receive copies the cell into the binding's slot (`ec_region_to_standard`) and frees the shell; an unreceived completion is released through the union's cell-form release (`handle_union_release_fn`, `emit.rs:31306-31396`). Rust's join handle likewise stores the output in the task's own allocation. An embedded call keeps the frame-region form. Pinned by `a_union_a_task_returns_is_received_and_narrowed_once` and its siblings, and the `maybe_union_program` cases (hit, miss, received, unreceived, a dropped group member; `v03_m9_c8_s6`). A received completion belongs to the receiving binding, as before.
- **Not released.** A channel or a handle a group member returns is not released from a returned member's slot (`callee_result_type` lists what is: a string, array, map, a `maybe` of a string, flat shape, decimal or envelope union, an envelope union, and an errors result of those, of a scalar or of a bignum; `release_returned_value`, `emit.rs:31532-31646`, rebuilds each form: the `maybe` pair as an envelope, the union, and a plain `maybe` of one, as its slot, the union result as the standard pair over a copy). A suspending `-> number<40>` (a bare bignum) does not compile today, so no member returns one (parked).

Pinned by `v03_m9_c8_s6` (one test per site, the parked-frame kinds, the unreceived results, the given shape), `v03_m9_c8_s0` (`dropped_while_pending_*`) and `drop_entry_contract` in `ynz-runtime` (the drop skips a returned and an unwound frame).

### Non-owned reads — view or copy

A read of a place someone else owns (`b.rows`, `rows[i].or(d)`, a loop's element, a call's argument) has two honest forms. A **view** points at the place: no allocation, as a Rust borrow. A **copy** owns a value of its own. Overwriting a place releases the value it held (the helper above), so a view that is still read after its place is written reads freed memory. Typeck therefore decides, per read, and codegen copies unless typeck proved a view. **Cost: no write while the reader lives means no copy; a write means one copy per affected `let`, loop iteration or call** (what Rust's `.clone()` costs where its borrow checker refuses a borrow), so Golden Rule 8 holds and the language gains no rule. Pinned by `v03_m9_c6_borrow_cost`.

**The record.** `TypedModule::non_owned_reads` (`crates/ynz-typeck/src/non_owned_reads.rs`) maps the span of the expression that reads the place to `View` or `MustCopy`. It is built in the ONE liveness walk of `string_ownership` (the same `after` sets as `string_moves`); nothing re-derives it. These sites are judged:

| site | reader | key | judged types |
|---|---|---|---|
| `let` value, reassignment value | the binding | the value expression | array, map, shape, union, `maybe` of those |
| `for` loop variable (array, `fixed`, map key and value) | the variable, live for the whole body | the iterated expression | string, bignum, array, map, shape, union |
| call argument at a position the callee only reads | the callee's parameter, live for the call | the argument | the same |
| `return` | none: it outlives its frame | no entry | string, array, map, shape, channel, `maybe` of a channel, envelope union (`copied_at_return`) |

**The copy sites, for C10's Golden Rule 8 check.** These are every place a non-owned read can allocate a copy, and the places a value moves instead. A row typeck judges (a view or a copy) has a no-write case pinned at zero extra copies and a write case pinned at one, in `v03_m9_c6_borrow_cost` (`crates/ynz-driver/tests/`); a row that always copies or always moves says so and names its pin.

### The parameter rule and how far it travels (FRAGO 007, re-derived)

A whole binding that is a parameter transfers only if declared `give`. With `give` declared, the EXISTING call-site path consumes the caller's binding (sink 2) at every call and every spawn — one mechanism. The obligation therefore transits the whole chain: A relays to B relays to C, C sends; C's parameter needs `give`; B passes its parameter to a give position, so B's needs `give`; up to the frame that owns the value as a local. `share` and `lend` parameters are refused by the same test — they are explicit statements that the caller keeps the value.

**Every frame of the chain is reported in ONE compile.** The earlier draft reported one frame per compile on the stated premise that typeck lacks a callee-before-caller ordering. The premise is false: the fixpoint IS that ordering. `consumed[B][i]` is true as soon as B's body sends its parameter, whether or not B declares `give`; A's call `B(x)` therefore sees a give position, and if `x` is A's own undeclared parameter, A gets its `ParamNeedsGive` in the same compile as B. For a LOCAL `x` at A, the call also consumes `x` in that compile (so A's later read of it is reported now, not after B is fixed) — the program is already rejected by B's error, so this consumption changes only what is reported, never what is accepted; the accept/reject decision stays signature-driven, which is why this is not the "infer `give` for bare parameters" alternative FRAGO 007 rejected (that alternative would have accepted a program whose caller's signature says nothing). Each error is independently actionable — one word in one signature — so N hops cost one compile, not N.

### `dynamic Contract` dispatch — covered by construction

A contract method's parameters carry ownership modifiers in the AST (`ContractSig.params: Vec<Param>`, each with `ownership`; the receiver's `ReceiverKind` too). **They are OPTIONAL there, exactly as on a function with a body** — the parser's contract-signature loop accepts a bare position (`parser.rs:3996–4012`, `_ => None`); the rule is the one the rest of the language already has: **a bare position is never a give position**, whether on a function (FRAGO 007 — `give` is written, never inferred) or on a contract (signed 2026-09-03, packet item (j) — `audit.md`'s SIGN-OFF record). A bare contract position is read-or-lend by the implementer's effective ownership, which is what the fixpoint computes for the implementing function; only a written `give` makes the dispatch site a transfer sink. `follows` parity is EXACT at the declared level for every non-receiver position — bare matches bare, `give` matches `give` — so an implementer cannot declare `give` where the contract is bare (the vtable would promise the caller keeps the value and the implementation would free it) nor the reverse. The receiver is checked for the half the parser lets it express: an explicit contract receiver modifier must match the implementer's exactly, and a bare contract receiver is never a give position (the implementer may not declare `give self`); the parser folds a bare contract `self` and "no self" into the same `receiver: None`, so "bare matches bare" cannot be distinguished from "no receiver" there and only the safety-relevant direction is enforced (SIGN-OFF item (j), `audit.md`). No parser enforcement is added. `ContractSigDef` (`shapes.rs`) carries `param_ownerships` (the declared modifier of each non-`self` param) and `receiver` (the declared receiver kind); the dynamic-dispatch site (`check.rs:~6153-6209`) builds the same normalized `[receiver, args…]` list `check_call_transfers` (`check.rs:5320`) runs for every other call form, and calls it with the contract's declared modifiers — the only static truth for a runtime-resolved callee; `follows` conformance checks that the implementing function's modifiers equal the contract's — otherwise the vtable would promise `give` and the implementation take `share`. Runtime exposure today is nil: codegen refuses every dynamic-dispatch call site ("dynamic dispatch call sites not yet lowered in M4 P4", confirmed by probe), so this closes a typeck hole before it can be reached, not a shipped crash. The `effective_ownership` fixpoint keys callees by name because the signature table does (`sig_table.fns` is one entry per name — no overloading is implemented); if overloading ships, both key by signature together.

### What this makes sound, and what stays outside

With every sink threaded through `check_transfer`, a transferred allocation has exactly one source-level holder at every moment: the owner (and its alias class) until the transfer, then the sink. The receiver of a channel is the sole reference; a `give` callee is the sole reference; a `background` task's ladder-owned clone is released by the shipped runtime protocol when the task sends it on ([`IMP-concurrency.md`](IMP-concurrency.md) "Two mechanisms, one rule" — unchanged by this section, and still not redundant with it: it answers allocation-level ladder ownership; this section answers source-level readability).

Outside the guarantee, named: relaying a RECEIVED owned-heap value — `let got = wire.receive()` then `other.send(got.value)` — where `got.value` is a piece of `got` (a `maybe<T>` field access, `Provenance::Reaches`), so `TransferNeedsCopy` fires and the relay pays `.copy()` this milestone (packet item (g), signed 2026-09-03).

**Two doors this section used to name as outside the guarantee are closed** (v0.3 concurrency
hardening Phase 3, FRAGO 002 cluster C2 — M8 Future Requirements #9 and #10, one fix at one
producer). Both came from the same design gap: two per-type dispatches answering "give me an
independent copy of this heap value", agreeing only by comment, and both defaulting to handing
back the receiver's own pointer.

- **FR#9's container door.** `bucket.add(rows)` into an aliased container was reachable because
  an `array<pointer-elem>` `background` argument was passed through un-cloned. Such an argument
  is now copied — items included — so the task's container and its rows are its own, and the
  ladder can no longer free something the spawner still points at.
- **FR#10's `.copy()` types.** `maybe`, union, `fixed`, `dynamic` and the rest no longer sit in
  an alias arm. Each is either a real copy or a compile-time refusal (`ynz_typeck::owned_copy`),
  so there is no type whose `.copy()` compiles into an alias for provenance to hold at arm's
  length.

**Deferred (four fields, packet item (g)): a consuming move-out-of-`maybe<T>` form.**
- **WHAT**: a consuming accessor on `maybe<T>` — some form that yields the wrapped value as `Provenance::Fresh` (moving it out of the `maybe` rather than reaching through it), so a relay of a received owned-heap value would not need `.copy()`.
- **WHY deferred**: the alternative to accepting the `.copy()` cost this milestone is a language-wide `maybe` semantics addition, which is outside a concurrency milestone's charter — `maybe<T>` is used everywhere in the language, not only at channel receives, so a consuming accessor's design (naming, what happens to the `maybe` binding afterward, whether it generalizes to every `maybe`-producing site) is its own design pass, not a corollary of the transfer rule.
- **COST to add later**: a `maybe` design addendum (the accessor's name and semantics), one new `Provenance` arm for it, and one codegen path to move the wrapped value out instead of reading through the envelope.
- **TRIGGER**: a measured relay workload where the extra `.copy()` per hop is a real cost, or the general move/drop story (Track 3 / FR 7(2)) landing and settling what "consuming" means for `maybe<T>` alongside every other heap type.

### Teaching text (Golden Rule 11; four diagnostics, one emit site)

**`ConsumedBySend`** — unchanged from Phase 1's drafting except one slot: because consumption is class-wide, the read name may differ from the sent name. `{name}` is the binding read, `{channel}` the channel; when the name read is not the name sent, `{via}` renders ` — it shares its value with \`{sent}\`, which is what was sent`.

> **WHAT**: `{name}` was sent into `{channel}` and cannot be used here — `send()` gave it away{via}.
> **WHAT INSTEAD**: If you still need `{name}` after sending it, send a copy instead: `{channel}.send({sent}.copy())`. If you only need it before the send, put this line above the `send()`.
> **WHY**: A channel hands the value to whichever task receives it, and that task may already be reading or changing it by the time this line runs. If both sides kept the same value, two tasks could change it at once and neither would know. So `send()` gives `{sent}` away, and the compiler refuses to build any line that reads it afterward. Nothing happens at runtime — `{name}` is not cleared or set to `none`; the program simply does not compile until this read is placed above the `send()` or the send takes a copy.

**`ConsumedByStore`** — the read of a binding a store handed over. `{name}` is the binding read, `{place}` the place with its backticks (`` `list` ``, `` `x.field` ``, the literal `` `[a, c]` `` or `` `{ first: a, second: c }` ``, `` `b` ``), `{stored}` the binding named at the store, `{copy_form}` the same store written with `.copy()` (for a literal, the whole literal: `{ first: a.copy(), second: c }`), `{via}` as in `Consumed` (` — it shares its value with `` `{stored}` ``, which is what was stored`).

> **WHAT**: `{name}` was stored in {place} and cannot be used here — storing a value hands it over{via}.
> **WHAT INSTEAD**: If you still need `{name}` after the store, store a copy instead: `{copy_form}`. If you only need it before the store, put this line above the store.
> **WHY**: Every value has one owner. Storing `{stored}` in {place} makes {place} its owner, and when {place} is done with it, it frees it. If `{name}` could still read the same value, two names would reach one value and one of them would free it under the other. So a store hands the value over, and the compiler refuses any line that reads `{stored}` afterward. Nothing happens at runtime — `{name}` is not cleared or set to `none`; the program simply does not compile until this read is placed above the store or the store takes a copy.

A refused store (a parameter, a piece, a loop cell) is `ParamNeedsGive` / `TransferNeedsCopy` with `{act}` = `handed to {place}` and `{copy_form}` the store written with `.copy()`.

**`ParamNeedsGive`** — `{name}` the parameter, `{fn}` its function, `{type}` its declared type, `{modifier}` one of `has no ownership word` / `is declared \`share\`` / `is declared \`lend\``, `{act}` one of `sent into \`{channel}\`` / `given to \`{callee}\`` / `given to \`{callee}\`, whose \`{param}\` parameter gives it away`, `{copy_form}` the matching `{channel}.send({name}.copy())` / `{callee}({name}.copy(), …)`:

> **WHAT**: `{name}` is a parameter of `{fn}` that {modifier}, but this line gives it away — it is {act}. Only a `give` parameter can be given away.
> **WHAT INSTEAD**: Declare it `give` in `{fn}`'s signature — `function {fn}(give {name}: {type}, …)` — so every caller hands the value over for good. If `{fn}` should leave its caller's value usable, give away a copy instead: `{copy_form}`.
> **WHY**: A parameter without `give` still belongs to the caller — the caller's own binding stays usable after `{fn}` returns. If `{fn}` could hand that value onward anyway, the caller and the new holder would both have it, and when the new holder is done with it and frees it, the caller would be reading memory that is already gone. `give` in the signature makes the caller's binding unusable after the call, so the value has exactly one holder at every step. If the caller's value is itself a parameter, that function needs `give` too — every function on the chain that lacks the word is reported in this same build.

**`TransferNeedsCopy`** (replaces the Phase 1 draft's `SendPayloadNeedsCopy`, whose WHAT — "not a named binding, so the compiler cannot tell who else holds it" — was the enumeration speaking; the compiler now knows exactly who holds it, and the diagnostic fires at every sink, not only at a send). `{act}` as above; `{expr}` the source text; `{type}` the type; `{reason}` chosen by provenance — `a field of \`{root}\`` / `an item inside \`{root}\`` / `one cell of \`{root}\`, which this loop is walking` / `what \`{callee}\` returns, and \`{callee}\` returns a piece of its \`{param}\` argument` / `a value the compiler cannot trace to one owner`; `{fix}` is `{expr}.copy()`:

> **WHAT**: This line gives `{expr}` away — it is {act} — but `{expr}` is {reason}, so someone here still holds it.
> **WHAT INSTEAD**: Give away a copy instead: `{fix}`. If you meant to hand over the whole thing, give the whole thing: the binding that owns it.
> **WHY**: Whoever receives a `{type}` will eventually free it. But `{expr}` is {reason}, so another holder may free it too: if the receiver and that holder both kept the one value, the same memory would be freed twice, and if one freed it first, the other would be left reading memory that is already gone. A `.copy()` belongs to nobody else, so it is safe to hand over.

Worked examples (the gallery renders these; `crates/ynz-driver/tests/error_galleries.rs` counts them):

function eatMaybe(give owner: maybe<array<int>>) -> nothing { print(owner.exists().toString()) }

function entrypoint() -> nothing {
  let bucket: Bucket = { rows: [1, 2, 3] }
  eat(bucket.rows)
  // COMPILE ERROR: This line gives `bucket.rows` away — it is given to `eat` — but `bucket.rows`
  //   is a field of `bucket`, so someone here still holds it.
  //   Give away a copy instead: `bucket.rows.copy()`. …

  let again = pick(held)
  eatMaybe(again)
  // COMPILE ERROR: … `again` is what `pick` returns, and `pick` returns a piece of its `b` argument …
  let matrix: array<array<int>> = [[1, 2], [3]]
  for (row in matrix) {
    eat(row)
    // COMPILE ERROR: … `row` is one cell of `matrix`, which this loop is walking …
  }
}

### What `EffectiveOwnership::Reads` proves, and the one honest extension

`crates/ynz-typeck/src/effective_ownership.rs` answers, for every parameter of every local function, whether the body — across every path, transitively through every callee — only reads it (`Reads`), definitely writes or moves it (`Writes`), or flows it somewhere unanalyzable (`Unknown`). `Reads` is the lattice bottom and is raised by any non-read use; every unclassifiable path is `Unknown`, never `Reads`. That is exactly the **task-side** half of the sharing question: a value passed to a `background f(v)` is read-only inside the task iff `report.ownership_of("f", i) == Reads` at `v`'s position, including through everything `f` calls. Directly reusable; no restatement.

It is NOT the **caller-side** half. The report is per parameter; the caller's `v` is usually a local, and the question there is "does `v` denote the same, unwritten value at every spawn of the group?" — the same classification over a different region, PLUS one thing the walker does not answer today. The honest extension has two parts, both in `effective_ownership.rs`:

1. `classify_binding_in_stmts(name, stmts)` — the existing `classify_param_in_block` exposed over a statement suffix (it matches names; it never depended on the name being a parameter). Same lattice, same walker.
2. **A rebinding of the name is `Writes` in that walker.** Before Phase 5 it was not: the `Stmt::Assign` arm of `effective_ownership.rs::classify_param_in_stmt` classified by the assigned VALUE only, and the arm's own doc comment said reassigning the binding "does not escalate" — correct for the question the walker was written for (does the body write THROUGH the parameter's value; a parameter cannot be reassigned at all — the `Stmt::Assign` arm of `check.rs::check_stmts` refuses it), wrong for the caller-side question, where `v = other` between two spawns means spawn 2 must see a different value than the block minted at spawn 1 holds (probe — `git log --grep=m8-p2`: `background render(scene, out); scene = other; background render(scene, out)` prints `1 + 7 = 8` today, each spawn copying the current value; an Arc group admitted across that `Assign` would print `2`). ONE predicate, `stmt_rebinds(stmt, name) -> bool`, true for `Stmt::Assign { target == name }`, `Stmt::Let { name == name }` and `Stmt::For` binding `name` (the same three binding-event forms of "Binding events, origin and alias classes" above — the exhaustive list, reused, not re-listed), is consulted by the walker's statement arm and returns `Writes`. Cost on the task side: none in accepted programs for `Assign` (a compile error on a parameter) and a lost `readonly` attribute on a parameter shadowed by a same-name `let` in its own body — the conservative direction, and a form no fixture uses. That arm's doc comment now says this.

No new classifier is written for the caller side. The group condition below reads the same predicate to place group boundaries, so "is this statement a rebinding of `v`" has one definition for both consumers.

A declared `share` parameter on the spawned function stays the hard error it is today (the `Expr::Background` arm of `check.rs::infer_expr`, "Cannot use `background` with a function that borrows its arguments") — Auto-Arc's task-side proof is `Reads` on a BARE parameter, the modifier the compiler infers. This section reopens nothing.

### The topology, decided

Two shapes were on the table:

| | (A) repoint the caller | (B) one shared copy, N task references, caller keeps its original |
|---|---|---|
| Who holds a reference | caller + every task | every task; the caller holds ONE transient reference for the lexical extent of the spawn group and reads through its own original, never through the Arc |
| Caller's release | at scope exit, through the scope-exit release pass (`Cg::emit_release_edge`, `crates/ynz-codegen/src/emit.rs:30830-30836`), which releases every heap local; (A) would still have to teach that pass a caller binding that is an Arc reference, and a spawn group inside a loop needs one caller-held reference across iterations | immediately after the last spawn of the group — a statically placed `ynz_arc_free` on a straight-line temporary; the release edge is not involved |
| Frame layout | the caller's binding changes representation (a stack shape alloca becomes a pointer into an Arc block) — the crossing-local / frame-slot / `sm_crossing_*` machinery would have to learn a new shape of local; R2's hazard class | the caller's frame is untouched; the transient is an ordinary local that dies before any suspension |
| Benefit at N = 1 task | none (one copy either way, plus a header and two atomics) | none — and no group forms, so the shipped `.copy` path runs unchanged |
| Benefit at N ≥ 2 tasks | one copy instead of N | one copy instead of N |
| Composition with the shipped `.give`/`.copy` inference | a THIRD path the caller's own reads must know about | a refinement of `Copy` for a group of spawns: every member records `Arc` instead of `Copy`/`Give`; the caller's usage rules are unchanged |

**Decision: (B).** One block at the first spawn of a group, held in a caller-side transient: `ynz_arc_new(struct_bytes, drop_glue)`, a byte copy of the shape into it, and a copy of each of the shape's `string` fields that the block owns ("What the block owns" below; `emit.rs:24601-24628`); `ynz_arc_clone` at every member spawn (including the first — the transient's own reference is separate; `emit.rs:24632-24638`); `ynz_arc_free(transient, size)` immediately after the last member's spawn statement (`release_pending_arc_transients`, `emit.rs:25231-25248`); each task's argument-drop ladder releases its reference through the `BG_ARG_KIND_ARC_SHAPE` arm calling `ynz_arc_free(ptr, size)` (`crates/ynz-runtime/src/runtime.rs:1191-1199`). Count: `new`=1, N clones → N+1, transient released → N, tasks retire → 0. The transient is what makes the group safe across the region between spawns: without it, task 1 could finish and free the block before spawn 2 clones it.

### What the block owns

The block is one counted allocation: a 16-byte header, then the shape's bytes. The header is the refcount (8 bytes) followed by the drop-glue pointer (8 bytes; null when the data owns no heap). Codegen holds and passes the DATA pointer, and the runtime finds the header 16 bytes before it (`ARC_GLUE_OFFSET`, `ARC_HEADER_SIZE` and `ArcDropGlue`, `crates/ynz-runtime/src/arc.rs:83-91`; `ynz_arc_new`, `arc.rs:118-123`).

**The block owns one copy of the shape's `string` fields, one per group, not one per task** (decided: Chief Architect, "one copy per group, like Rust's `Arc<T>`"; `git log --grep="Arc block owns"`). A byte copy of the shape alone would point the block at the spawner's strings, which the spawner's scope exit releases while a task may still read them. The protocol, in order:

1. **First member: mint.** The glue is the shape's own release function from the one release helper, `Cg::release_fn(shape, false)` (`emit.rs:24603-24610`; `release_fn`, `emit.rs:29334-29345`): it frees each field the shape owns and not the cell, and a shape that owns no heap has none, so the glue is null. Then `ynz_arc_new(size, glue)` (`emit.rs:24611-24618`), the struct bytes stored into the block (`emit.rs:24619-24625`), and `deepen_shape_fields(block, name)` (`emit.rs:24626`; `deepen_shape_fields`, `emit.rs:5924-6002`), which replaces each string field in the block with a fresh copy through `emit_owned_copy` (`emit.rs:5993-5995`). The spawner's own shape and strings are untouched: it keeps reading and releasing them as for any local.
2. **Every member: clone.** `ynz_arc_clone` takes the task's reference (`emit.rs:24632-24638`). The last member queues the transient's release (`emit.rs:24639-24642`).
3. **Last release: glue, then free.** Whichever holder drops last — the caller's transient, a task's drop ladder or the CPU-arm closure free — calls `ynz_arc_free(ptr, size)`; the one that takes the count to zero reads the glue slot, runs the glue on the data (releasing the block's string copies), then frees header and data (`arc.rs:147-167`). A release that is not the last runs nothing, so each copy is released exactly once. No release site passes a glue argument of its own: the glue lives in the block.

The floor that makes this enough is `arc_shareable` (`crates/ynz-typeck/src/types.rs:435-467`): it admits only a shape whose every field is `int`, `float`, `bool` or `string`, and `string` is the one heap kind the block owns a copy of. A shape with any other heap field is not a group member (the per-task copy path runs). The runtime declaration codegen emits is `ynz_arc_new(i64, ptr) -> ptr` (`ArcDecls`, `emit.rs:25193-25224`).

Pinned by `crates/ynz-driver/tests/v03_m9_c1o_arc_owned_copies.rs` (ASan at both optimization levels, allocations = frees): `a_string_field_of_an_arc_group_shape_outlives_the_spawner_and_is_freed_once` (fixture `v0_3_m9_c1o_arc_string_field.ynz`) and `every_string_field_of_a_cpu_arm_arc_group_shape_is_owned_by_the_block` (CPU-arm closure free, two strings, fixture `v0_3_m9_c1o_arc_cpu_arm_two_strings.ynz`); and by the runtime unit test `drop_glue_runs_once_on_the_last_release_with_the_data_intact` (`arc.rs:209-243`).

### The beneficial-emission condition (the registry entry's own `why`)

Arc is emitted for binding `v` iff ALL hold, checked by `check.rs::admit_arc_group_for` (run from `admit_arc_groups_from` at the first `background` statement of a candidate group, inside the statement-form pass `check_stmts`) where the group is visible:

1. **≥ 2 spawn statements in one block pass `v` as a whole binding** (`Provenance::Whole`), by any spawn form (`background f(v)` or `let h = background f(v)`), with no suspension point between the first and the last (a suspending statement between them ends the group — the transient would have to cross a frame boundary, which is exactly the layout interaction R2 warns about; a later milestone may widen this with the crossing-local plumbing, recorded as the residual below). **The caller after spawn-return plus ONE task is NOT a sharing case under (B)**: the caller reads its own original, the task reads its copy — that is the shipped one-copy path, and an Arc would add a header and atomics for nothing. The plan's step-3 alternative ("caller + ≥1 task") is beneficial only under (A), which would need the scope-exit release to treat the caller's binding as an Arc reference.
2. **Task-side read-only proof**: for every member, `report.ownership_of(callee, position) == Reads`. `Unknown` or `Writes` on any member declines the whole group (a task that writes needs its own copy — today's semantics, unchanged).
3. **Caller-side same-value proof**: `classify_binding_in_stmts(v, stmts[first..=last]) == Reads` — the member `background` statements THEMSELVES and everything between them — where a rebinding of `v` is `Writes` (extension part 2 above). A write between the members means the later task must see the updated value, which a block minted at the first member cannot provide; decline to `Copy` (today's per-task copy sees the current value). **The members are inside the walked range, not just the statements between them**: a write can hide in a member's own argument list — `background render(scene, results, bump(scene))` with `bump` declared `lend` — and arguments are prepared in order, so the block would be minted from `scene` BEFORE `bump` ran and the next member's clone would read stale bytes (Phase 5 fix round 2, `red:code-reviewer`: the shipped range was `first + 1..last`, the group was admitted, and task 2 printed the stale `6` where the copy path prints `106`; fixture `m8_arc_write_in_member_arg_declines.ynz`). The walker's `Call` arm already returns `Writes` for a declared `lend`/`give` position, and the whole-binding member positions classify `Reads` from the same report the task-side proof read — no second classifier. **A rebinding of `v` at the TOP LEVEL of the spawns' own block — `v = …`, a shadowing `let v`, a `for (v in …)` — is a GROUP BOUNDARY, not a decline**: the group closes at the last spawn before it and a new group opens at the next spawn after it, each judged on its own member count (a one-member segment is the shipped copy path). Why a boundary and not `Writes`: a rebinding does not make sharing unsound, it changes WHICH value is shared — spawns before it read value A, spawns after it read value B, and each segment is a correct group in its own right; declining all of them would forfeit a sound sharing for no soundness reason, and `admit_arc_group_for` already walks the block by statement index to find the spawns, so placing a boundary is the same bookkeeping "no suspension between" already needs — one more delimiter of the same kind, read from the same `stmt_rebinds` predicate. A rebinding INSIDE a nested block between two spawns (`if (…) { v = other }`) is `Writes` and declines the enclosing group: which value spawn 2 sees is then path-dependent, and no statically placed block is right on both paths. A nested shadowing `let v` does not rebind the outer `v`, but the walker's same-name tracking classifies it `Writes` too — over-conservative, safe, and not worth a frame-aware twin of the walker.
4. **Arc-shareable type**: ONE predicate `arc_shareable(ty)` in `ynz_typeck::types` (`crates/ynz-typeck/src/types.rs:435-467`), the compile-time floor `arc.rs` documents — a `shape` whose fields are all `int`/`float`/`bool`/`string`; the block owns a copy of each `string` and releases it with the last reference ("What the block owns" above). Excluded: `number` fields (two reasons: 16-byte alignment, the block's data is 8-aligned; AND a shape with a `number` field SIGSEGVs on ANY `background` spawn today on the copy path, parked item 40 / FRAGO 012, hotfix pending — the floor must not widen to `number` until that lands), `array`/`map`/`maybe`/union/`channel` fields (pointer cells whose ownership the block cannot express — sharing the outer bytes would alias the inner allocation between tasks with no count on it), **nested `shape` fields** (the signed text said "inline `shape`"; Phase 5 found the tree stores a nested shape field as an opaque POINTER inside the struct — `ShapeTypeBuilder::field_type`, `crates/ynz-codegen/src/shape_types.rs:305-359` — so it is a pointer cell exactly like an array field, and the implementation excludes it), and every non-shape type (`array<int>` bg args are cloned by `ynz_array_clone_primitive`; refcounting a header-plus-buffer pair is a different substrate, named in the residual).

**One boundary Phase 5 added beyond the signed list (item 1)**: a statement containing a `return` at any depth between two spawns is a group boundary. The transient's release is straight-line code placed after the last spawn; an early exit between the spawns would skip it and leak one count (never a free-early). The implementation's suspension test is deliberately conservative and syntactic (`stmt_may_suspend_conservative`: any `wait`, any call to a function the may-block fixpoint marked suspending or to a base suspension intrinsic, any call through a non-identifier callee, any `send`/`receive` method call on any receiver) because expression types of the statements ahead of the spawn are not yet inferred when the admission runs; over-approximating only declines to the shipped copy path.

Loops are out: `for (…) { background render(scene) }` is ONE spawn statement, so no group forms and the shipped per-iteration copy runs. A cross-iteration Arc would need a caller-held reference that outlives the statement, which the straight-line transient does not give. Recorded in the residual.

When any condition fails, **nothing changes**: the shipped `Give`/`Copy` inference records exactly what it records today and `prepare_bg_arg_for_ctx` heap-copies per task. Phase 5 step 3 confirms that path byte-identical.

### What typeck records and what codegen reads (no re-derivation)

`BgOwnership` gains `Arc { group: GroupId, first: bool, last: bool }`, recorded for every member of an admitted group by the ONE spawn-argument recording function all three recording sites share (`check.rs::check_stmts` for the statement form, `check.rs::check_background_handle_spawn` for the handle-form pre-record, and the `Expr::Background` arm of `check.rs::infer_expr` as the backstop). That shared function also fixes parked item 16: the handle form records `Copy` unconditionally today even when the callee's `give` consumed the binding, so a hint reading `bg_inferred` would say "copied" for a value that was given. Codegen reads the recorded variant (`emit.rs:24579-24584`) and emits `arc_new(size, glue)` + memcpy + a copy of the strings + `clone` (first), `clone` (member), `arc_free(transient)` after the last (`emit.rs:24601-24643`); it consults no ownership fact of its own.

The runtime's release protocol (`release_ladder_payload`, pointer identity) never meets an Arc'd shape: shapes are not channel elements (deferred) and are returned by value (v0.3-M7 R9). **Decided (Phase 5, packet item (h)): `bg_arg_kind_is_releasable_payload(BG_ARG_KIND_ARC_SHAPE)` is `false`.** The slot holds one COUNT on a block other tasks also count, not a payload the task owns outright; if a future hand-off ever matched it, skipping the ladder's release leaks one count (bounded, reported by the alloc/free parity gate) while releasing it under a receiver would be a use-after-free — `false` picks the leak side by construction. Pinned by the runtime's per-kind parity test (`channel::tests::every_bg_arg_kind_is_releasable_iff_the_ladder_frees_it_alloc_free_parity`), which stages the Arc kind with a live co-owner: the ladder's retire frees nothing, the co-owner's release frees the block once.

### Override directions ([`auto-promotion.md`](../../../.claude/rules/auto-promotion.md))

- **Force the OTHER pick (independent copies despite a group)**: write `background render(scene.copy())` at the spawn you want independent. `.copy()` is `Provenance::Fresh`, not `Whole`, so that spawn is not a group member; it takes the shipped per-task copy path (`prepare_bg_arg_for_ctx`'s explicit-`.copy()` arm). Existing, typeable syntax; no new API. **Correction to earlier text**: [`IMP-concurrency.md`](IMP-concurrency.md) "Ownership with Background Tasks" and the v0.3-M8 plan both named `.give` as a spawn-site override. No body-level `.give` exists — `PostfixOpKind` is `Copy | Freeze`, and this document's read-first note says so. The give direction is already what the liveness inference does for a binding unused after the spawn; there is nothing to force.
- **Force the AUTO pick (Arc when the compiler would not)**: deliberately no override. Every decline above is a soundness decline (a writer, an unprovable callee, a type the block cannot express) or a zero-benefit case (one task, a loop); forcing sharing through any of them either races or costs more than it saves.
- **`share` at a `background` boundary** stays a compile error. It is not reinterpreted as "Arc this": a `share` parameter is a borrow of the caller's frame, and the spawned task may outlive that frame; the Arc block is not the caller's value, it is a copy the tasks own.

### The muted hint (`auto_arc` domain, Informational category; live since Phase 5)

Inline: `// shared by reference count with {n} tasks — read-only` — `{n}` is the group's member count, read from the same `BgOwnership::Arc` record codegen emits from. The hover is static registry markdown (`ynz_registry::lsp_inlay_hint_hover_for` substitutes nothing), so the registry text says "each `background` task started here" where the draft below writes `{n}`; the count is in the label. The draft, tied to the actual group:

> **WHAT**: This value is copied once into a shared block, and each of the {n} `background` tasks started here holds a counted reference to that one copy instead of getting its own full copy. Your own binding is untouched — you keep reading your original.
> **WHAT INSTEAD**: Nothing to type — the compiler picks this when {n} tasks only read the value and nothing changes it between the `background` statements. If one task needs its own version to change, pass `{name}.copy()` at that `background` statement so it gets an independent copy.
> **WHY**: {n} tasks read this value, so one shared copy saves {n − 1} full copies. Each task pays a tiny bookkeeping step when it takes and drops its reference — cheaper than a copy here, which is why the compiler shares only when at least two tasks read it.

The red-tint styling stays under `auto-arc-cautionary-tint` (no per-hint tint path in `ynz-lsp`); the caution is in the words.

### Residual (`auto-arc-codegen-emission` is narrowed to exactly this)

- Spawn groups that straddle a suspension point (needs the transient to be a crossing local).
- Spawn groups inside a loop (needs a caller-held reference across iterations).
- `array`/`map` values and shapes with pointer-cell (`array`/`map`/`maybe`/union/`channel`/nested `shape`) or `number` fields (a different sharing substrate; `arc_shareable` is the floor — and `number` stays out for the second reason above, parked item 40, until its copy-path hotfix lands).
