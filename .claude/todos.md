- [ ] **`v0-3-m3c-array-by-value` — array<Shape> by-value element storage (lift `ArrayShapeRuntimeFieldWithWait`)** — PATRICK-APPROVED long-term fix (2026-06-04): "We need it fixed long term." **Why**: `array<Shape>` stores element POINTERS to stack allocas (uniform 8-byte `YnzArray` slots + `ptr_to_int`); for shapes with RUNTIME field values, those allocas dangle when the function suspends (stackless SM frees its stack) → silent stack-garbage miscompile across a `wait`. - [ ] **per-binding-slot shadow support (lift `ShadowsCrossingLocal`) — full variable shadowing across suspension boundaries** — Yinz ALLOWS shadowing (`design/linting.md` `shadowed-variables` lint = warn, not error; `spec/linting.md:146`). It works in NON-async functions (round-6 codegen fix: entry-block alloca + restore-all). It does NOT work inside state-machine (async) functions: the frame-slot system keys crossing-local slots by NAME, so two same-named bindings around a suspension share one slot and the second write clobbers the first. Today that's a clean compile error ("rename the inner binding"). **Why it MUST stay a clean reject until lifted** (NOT a partial fix): v0.3-M3a Phase 2 round 6 tried to partially lift it (allow non-crossing shadows in SM functions) and hit the EXACT silent-wrong-answer the deferral doc predicted — `reload_params_from_frame` writes the resumed value into `cg.locals[name]` which the shadow redirected to the shadow's alloca, leaving the real binding uninitialized → garbage read. Round 7 reverted to the conservative reject. **Cost to lift (1-2 sessions, per `design/concurrency.md:301`)**: assign each `let` a unique binding ID (source span or monotonic counter); key crossing-local frame slots by binding ID not name; propagate ID-keyed resolution through flush/reload + typeck so "same name, different slot" is distinguishable at every read/write. **Trigger** (`design/concurrency.md:303`): user demand for re-using a name around a suspension in a program that can't be restructured, OR when per-binding slot identity is added to the crossing analysis + codegen. **Cross-refs**: `design/concurrency.md:241-305` (`ShadowsCrossingLocal` spec), `registry/features.toml:1135` (`shadow-crossing-local-support` deferred feature). **Workaround (always)**: rename the inner binding — which the `shadowed-variables` lint already suggests, so this restriction is consistent with Yinz's shadow-discouraging design, not a deficiency.
