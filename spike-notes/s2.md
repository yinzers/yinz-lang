## Q1: can two live bindings share one name-keyed slot?  YES (guard has holes)
Mechanism: the guard (check.rs ~1540-1700) only fires when the OUTER binding is a TOP-LEVEL `let`
(or a param) that crosses (`outer_is_genuine_crossing_local`). Nested outer bindings, for-loop vars
and non-crossing shadows of a crossing NAME are never examined. Codegen then keys everything by name:
crossing set is deduped by name (check.rs crossing_local_names_with_provenance), one slot per unique
name (emit.rs crossing_local_total_slots), one alloca per name (`is_sm_crossing`, emit.rs ~13890,
name-keyed even for a binding that does not itself cross), per-name type = FIRST `let` of that name
(emit.rs find_let_typeck_type_in_stmts / check.rs find_crossing_local_typeck_type_in_map).

Plain-alloca path is binding-correct only when the NAME is not in the crossing set: every non-crossing
`let` gets its own entry-block alloca with scope snapshot/restore (p14, p21).
So the prediction's second half is true only for names no binding of which crosses.

## Q2: can releases key by binding without changing slot identity?  NO
- Compile-time keying cannot help: at runtime both bindings are one alloca + one frame slot, and the
  outer value is lost at the inner store (p02/p24). A release can only free "what the slot holds".
- Release kind would also be wrong: the per-name type is the first `let` of that name (p26/p28/p29),
  so a string-vs-int sibling pair would release the second binding with the first one's type.
- Works only for the sequential same-name, same-kind case (p01/p11/p13/p25), if release nulls the slot.
- Alternative that avoids slot identity = widen the guard to reject any name bound twice in a
  suspending fn when any binding of it crosses. ~40 LOC, but rejects p01/p11 (two sequential loops
  with the same var name) and flips fixture v0_3_m3a_p1_disjoint_sibling_scope_shadow. A language
  restriction, not a release-pass change: needs a product call.

## Q3: smallest slot-identity change
Proven sufficient by hand (spike/s2/renamed/*): giving every colliding binding a unique name, with NO
codegen change, fixes p02, p09, p12, p23, p26 (correct output; spike/s2/renamed/p*_renamed.ynz).
So the smallest change is a binding-uniquifying (alpha-rename) pass, not ID-keying the codegen:
1. New pass `uniquify_bindings(&FunctionDecl) -> FunctionDecl` (one place, e.g. ynz-typeck): scope-stack
   walk over Stmt (Let, For var, For destructure_pattern + map_destructure_pattern, If/While/Match/else
   blocks) and all Expr kinds holding Ident/names (16 Expr variants incl. interpolated strings, calls,
   method calls, Assign target, FieldAssign, IndexAssign, Background args); rename the 2nd..nth binding of a
   name to `name__N` (the `__ynz_` prefix is already reserved against user code). ~200-300 LOC. A missed
   Ident fails loudly (`undefined ... in codegen`), not silently.
2. Call it where the AST is consumed by name: check.rs:1260 and :12721 (crossing + guards), emit.rs:332 and
   :779 (layout), :4731 (resume fn setup), plus the lowering of the SM function body: 5 sites.
3. Delete the guard (check.rs ~1540-1700, helpers find_shadow_in_stmts, outer_is_genuine_crossing_local,
   has_top_level_let_after_suspension, param_has_nested_let_shadow, has_top_level_let_in_stmts, the
   check.rs:12800 mirror, `for_var_elem_type_conflict` D5) and flip the 5 rejected fixtures
   (v0_3_m3a_p1_shadow_*/..._adv10/_adv11, v0_3_m3a_p2_* rejected set) to compile-and-run.
4. Diagnostics/LSP show renamed names only if the pass mutates the shared AST: run it on a clone for
   typeck-guard/codegen, never on the user-facing AST.
Size: ~1 session (pass + 5 call sites + fixtures), well under the doc's "1-2 sessions" for ID-keying all
13 `sm_crossing_*` structures (~150 refs in emit.rs) + cg.locals. Precedent for synthetic unique slot
keys: `__ynz_for_idx_N` already counter-keyed.
Interim if plan #17 cannot wait: the 40-LOC widened guard above makes the prediction true by construction.
