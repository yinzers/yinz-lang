# Spike S1 — is freeing `string` bytes sound as strings are built today? (scratch; never merged)

Verdict: NO. Prediction REFUTED as stated (see Q-answers). Line numbers = this branch's spike commit (emit.rs is +~60 lines vs main after line 4395 because of the scratch helper).

## Setup (reproduce)
- Toolchain (not in image): rustup stable + Debian LLVM 18.1.8 debs (`llvm-18-dev`, `libllvm18`, ...) extracted locally; `LLVM_SYS_181_PREFIX` -> extracted `usr/lib/llvm-18`; `RUSTFLAGS=-L <dir with libz/zstd/tinfo/stdc++/ffi .so dev symlinks>`. `cargo build -p ynz-runtime && cargo build -p ynz-driver`.

No free on explicit `return`; params never freed. `ynz-driver/src/build.rs`: `YNZ_SPIKE_LINK_EXTRA` adds linker args (`-fsanitize=address -g`).

ASan intercepts libc malloc/free/strlen/puts/memcpy; Yinz code and the Rust runtime are not instrumented, so UAF is caught only through libc calls (all string reads here go through strlen/puts/CStr).

## Representation (facts, read then confirmed by runs)
- `string` = bare `ptr` to NUL-terminated UTF-8 bytes. NO flag, header, length or capacity. IMP-strings.md's 24-byte SSO `YnzString` is NOT implemented. Provenance is not recoverable from the value.
- `owned_copy_plan(String) = ReceiverIsCopy` ("immortal immutable bytes"): crates/ynz-typeck/src/owned_copy.rs:151-153 (header comment :50-52). So `.copy()`, spawn args, `let b = a` are pointer copies BY DESIGN, not by omission.
- Every backtick literal parses to `Expr::InterpolatedString`; `Expr::StringLit` (emit.rs:15828) is only for `Token::StringLit` (parser.rs:2697). String `+` is a type error; `ynz_string_concat` is declared (runtime_decls.rs:616) but never emitted.

## Q2 — can scope-exit release free owned bytes without freeing shared/static ones? What marks the difference?
- Not as things stand: nothing marks it. Four independent hazards, three of them not "literals":
  1. STATIC bytes: literals (2 sites), bool globals, "[REDACTED]", error message.
  2. THREAD-LOCAL buffer: int/float/decimal -> string (and its overwrite-on-next-call semantics, t06 — which is already a latent aliasing bug if two are held).
  3. ALIASING: every copy (`let`, `.copy()`, field, array/map element, channel, spawn arg, param) shares one pointer, so N locals freeing = N-1 double frees, or UAF across threads/callees.
  4. DYNAMIC provenance: `names[9].or(\`none\`)` (t23) is the element or a static literal depending on runtime data, so compile-time provenance ("this let came from a literal / a call") cannot decide it. A compile-time-only mark is insufficient; either copy on bind, or the mark must be in the value.
- Candidate marks (none prototyped):
  - A. Header in the bytes: `[refcount|IMMORTAL][bytes...]`, pointer points at bytes (same trick as arc.rs, header at ptr-8). Literals/bool/redacted emitted as `{i64 IMMORTAL, [N x i8]}`; release = no-op on IMMORTAL else atomic dec + free at 0; copies retain. Pointer ABI stays one `ptr` (no change to channel/spawn/array cells). Handles dynamic provenance (t23) and cross-thread (t15/t28/t34) soundly.
  - B. Owned-copy-on-bind (prediction route): every bind/store/send/spawn makes a fresh heap copy, so exactly one owner per pointer; literals stay static but are always copied when bound. Needs a one-bit "static" knowledge anyway for the release (a literal-initialised local that was not copied must not be freed) -> still needs compile-time provenance + t23 forces a copy at every `.or(default)`; allocation per bind (Golden Rule 8 cost; needs Patrick if it exceeds hand-written Rust).
  - C. Typeck move/borrow tracking for `string` (give/lend/share like shapes) + owned vs borrowed distinction: the largest; also still needs fixes 1 and 2.
  - D. Leave `string` out of the release pass by recorded decision (plan allows it): leak per interpolation; zero risk; no work.

## Q3 — is a string-ownership change needed first, and how big?
Yes, before C3 may free string bytes (unless D). Estimated size for A (recommended if strings are to be freed):
- Runtime (~8 fns, 1 file): add header on all four allocators (lib.rs:1622 from_static, :1794 concat, :2147 builder_finalize, :2171 heap_string_from_str, + codepoint_at :1854); replace the 3 thread-local `*_to_string` buffers (lib.rs:112/186/205) with heap strings (this also fixes t06 clobbering); add `ynz_string_retain/release`; make sensitive/"[REDACTED]"/error-message/bool constants IMMORTAL-headed.
- Codegen: literal globals become headered (3 sites: emit.rs:15828, 16808, runtime_decls bool/redacted globals); retain sites at every copy: `Stmt::Let`/assign, struct-lit field store, array add/set/literal, map set, channel send, spawn arg (add a `String` arm to `owned_copy_plan` -> `StringRetain`, today `ReceiverIsCopy`, owned_copy.rs:153), `.or()`/`get` readers; release at scope exit (C3's pass) and in container teardown glue (runtime_decls.rs:118 notes the glue is null for string elements today -> arrays/maps/shapes need string-element release).
- Files: ynz-runtime/src/lib.rs, ynz-codegen/src/{emit.rs (~25-30 sites), runtime_decls.rs}, ynz-typeck/src/owned_copy.rs, shape/array/map drop glue; tests: ASan-run probes of every row above.
- Effort: ~4-6 engineer-days incl. tests (runtime header + literals ~1 d; retain/release at ~25 sites ~2-3 d; container teardown ~1 d; ASan matrix ~1 d). B is similar in site count but costs an allocation per bind; C is larger (typeck + diagnostics), weeks.
- Independent of the scheme: fix the thread-local buffers (lib.rs:112/186/205) — they are a bug source even without freeing.

## Prediction check
> "Freeing is unsound today only because string literals point at static bytes and some copies are shallow; an owned-vs-static mark plus routing copies through `emit_owned_copy` makes it sound."
REFUTED in part:
- "only because literals ... static": false — thread-local buffers, bool/redacted/error-message statics and dynamic `.or(default)` provenance are separate failure classes (t05, t31, t32, t23).
- "some copies are shallow": false — ALL copies are shallow, by design (`ReceiverIsCopy`, owned_copy.rs:151-153); there is no deep path for strings to "route through".
- "owned-vs-static mark" is necessary but not sufficient: with a binary owned/static mark, aliasing (t03/t12/t13/t14/t15/t26/t35) still double-frees; it needs reference counting (A), copy-on-bind (B) or move tracking (C).
- "routing copies through emit_owned_copy": emit_owned_copy is the right single choke point for copies (spawn arg + `.copy()`), but it is not where `let b = a`, field stores, array/map stores and channel sends go (they lower inline); those sites each need touching. Confirmed in part: that it is the correct seam for the spawn/.copy() consumers.
